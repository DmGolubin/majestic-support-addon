# Два публичных варианта и GitHub Releases

Единая версия, канал и репозиторий заданы в `distribution/config.json`.
Пакеты предназначены для Windows. Публичный выпуск содержит ровно два варианта:
**SupportTemplates Lite** (`standalone`) и **SupportTemplates для BetterDiscord**
(`betterdiscord`). Имя ZIP Lite остаётся `SupportTemplates-standalone-<version>.zip`,
имя плагина — `SupportTemplates.plugin.js`. Машинные идентификаторы не меняются.
Общий UI и ядро остаются в одной кодовой базе; изменения используются обеими поставками.
Сборка не меняет установленный Discord.

## Сборка

1. Зафиксировать изменения исходников коммитом.
2. Выполнить `node distribution/prepare-upstream.mjs`: создаётся отдельный checkout
   зафиксированного Vencord, зависимости устанавливаются указанной upstream версией
   pnpm с `--frozen-lockfile`. Установленный Vencord не изменяется.
3. Установить `VENCORD_DIR` в путь `checkout` из последней строки результата.
4. Выполнить проверки типов и `npm test -- --maxWorkers=4`.
5. Выполнить `node distribution/build-release.mjs`.
6. Выполнить `node distribution/publish-release.mjs --check`.

Комплект появляется в `artifacts/distribution/<version>/`. Повторная сборка не
перезаписывает существующий комплект: перенесите предыдущий комплект в архив.
Публичная сборка последовательно выполняет `standalone/build.mjs`, затем
`betterdiscord/build.mjs`. Исходники Vencord нужны как основа Lite; полный Vencord
этой командой не собирается.

Полный Vencord + SupportTemplates предназначен только для владельца и по-прежнему
собирается отдельно через `node distribution/vencord/build.mjs`; детали в
`vencord/README.md`. Его пакет храните отдельно от каталога публичного выпуска.
Общий updater сохраняет поддержку его машинного идентификатора `vencord`.

## Публикация

Для анонимной загрузки обновлений репозиторий из `distribution/config.json`
должен быть публичным, а выпуск — опубликованным. Токены сотрудников в плагин
не добавляются.

Команда `node distribution/publish-release.mjs` создаёт **черновик** выпуска
со всеми готовыми файлами; она требует авторизации GitHub CLI владельца.
Перед этим исходный коммит сборки должен быть отправлен в репозиторий: тег выпуска
привязывается именно к нему, а не к случайному последнему коммиту ветки.
После проверки опубликуйте этот черновик в GitHub. Для нового выпуска вместо
черновика можно явно вызвать команду с `--publish`. В приватном репозитории
выпуск доступен участникам, а анонимные автообновления остаются недоступны. Существующие выпуски команда не перезаписывает.

Проверка, создание черновика и `--publish` требуют ровно `standalone` и
`betterdiscord` в манифесте, их штатные имена и типы, соответствующие build-evidence
и корректные SHA-256. Разрешены только эти два файла, манифест, исходники,
SHA256SUMS. `build-evidence.json` и
`INSTALL-RU.md` остаются локальными файлами сборки: первый используется для проверки,
второй — как описание релиза. Вложения GitHub и SHA256SUMS их не содержат.
Дополнительный пакет, включая полный Vencord, отклоняется даже с верной
контрольной суммой. Старые комплекты из трёх вариантов этим скриптом не публикуются.

Также есть ручной GitHub Actions workflow `Build two public Windows distributions`.
Он собирает и проверяет комплект, сохраняет его как Actions artifact и только
при включённом `create_draft` создаёт черновик. Автоматической публикации нет.

Для следующего обновления увеличьте версию в `distribution/config.json`,
соберите оба публичных варианта и опубликуйте новый выпуск `v<version>` вместе с
`support-templates-update.json`. Один push исходников обновление не выпускает.
Canary-выпуск должен быть отмечен prerelease. Обновлятор видит только опубликованные
выпуски своего канала и своего варианта; `/latest` не используется.

SHA-256 защищает от повреждения пакета; доверие издателю основано на HTTPS и правах
записи в указанный GitHub-репозиторий. Это не отдельная цифровая подпись.
Подробная схема и границы обновлятора: `updater/README.md`.

Документация платформ: [Vencord custom plugins](https://docs.vencord.dev/installing/custom-plugins/),
[BetterDiscord plugins](https://docs.betterdiscord.app/plugins/introduction/quick-start),
[GitHub Releases API](https://docs.github.com/en/rest/releases/releases).

Первый выпуск 1.0.1 публикуется напрямую по решению владельца. Будущие обновления
после релиза проходят PR и проверку Дмитрия перед сборкой и публикацией.

В компактном ZIP снаружи находятся два BAT и папка `SupportTemplates/`; манифест,
payload, служебные скрипты и соответствующие исходники лежат внутри неё.
Для перехода с Lite 1.0.1 нужен один ручной пакет; старый установленный helper
не знает вложенную структуру. Новый helper принимает и прежний, и компактный формат.
