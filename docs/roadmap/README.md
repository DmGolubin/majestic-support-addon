# Roadmap

`data.json` — единственный актуальный список задач. Сайт, `docs/STATUS.md` и `TODO.md` используют его; старые аудиты остаются доказательствами исторических проверок.

## Открыть

Из корня репозитория: `pnpm roadmap:serve`, затем http://127.0.0.1:47834/roadmap/.

Нужен Python 3. Сервер доступен только на этом ПК и обслуживает каталог `docs`. После перезапуска ПК запустить снова. Публичного размещения нет.

## Обновлять

На первом экране три независимых результата: показ в Discord, выпуск команде и подключение сайта. В каждом видны готовность и следующий шаг, подробные шаги раскрываются по нажатию. Готовое демо не делает готовым выпуск или API. По умолчанию ниже показаны ближайшие задачи; «Весь список» открывает весь план, «На потом» — отложенное. Нажатие на шаг показывает конкретную задачу и её доказательства.

- Новая задача: добавить объект в `data.json` с уникальным ID, областью, статусом, описанием, датой и ссылками на доказательства относительно `docs`.
- Перед работой: `node scripts/roadmap.mjs set R01 active "Что выполняется сейчас"`.
- После реализации, если обязательная приёмка впереди: статус `review`.
- После завершения описанного объёма: `done`, с результатом и ограничениями проверки в описании.
- Будущие задачи: `planned`; ожидание серверного API: `blocked`; сознательно перенесённые идеи: `deferred`.
- После ручного изменения JSON: `pnpm roadmap`.
- Перед коммитом: `pnpm roadmap:check`.

Генератор проверяет ID, статусы и существование файлов доказательств. STATUS включает все задачи, TODO — только незавершённые. Их не нужно редактировать вручную.

Открытая страница перечитывает JSON каждые 5 секунд; поиск, фильтры и раскрытые задачи сохраняются. При недоступности сервера показывает последнюю загруженную копию с предупреждением. Сайт не запускает агента и не выполняет задачи в фоне. Правило вести список во время работы закреплено в корневом `AGENTS.md`.
