# Диагностика для тестера

Доступна начиная с локальной сборки `1.0.1-canary.21`. Запись выключена по умолчанию.

1. Откройте Settings плагина в BetterDiscord либо «Настройки» внутри SupportTemplates.
2. Включите **«Записывать диагностику на 24 часа»** и пользуйтесь плагином как обычно.
3. Сразу после проблемы нажмите **«Скачать диагностику»**. Пришлите полученный `SupportTemplates-diagnostics-….json` вместе с примерным временем и описанием того, что ожидали увидеть.

Если понадобился Ctrl+R, история сохраняется в локальном профиле. После перезагрузки можно скачать файл даже без повторного входа в панель. Ничего не отправляется разработчику автоматически. Запись можно выключить раньше; удаление журнала требует отдельного нажатия подтверждения.

## Что содержит файл

- Версию и сборку плагина; текущее состояние подключения и интерфейса, безопасные настройки, размеры viewport и измеренные затраты работы плагина. Неизмеренные long tasks обозначены явно.
- Последовательность действий плагина и пользователя: открытие/закрытие окон, вставки и их результат, начало входа, выход, смену аккаунта Discord, запуск и остановку runtime.
- Запросы **плагина к панели**: нормализованный путь без ID/параметров, метод, номер запроса, фактический HTTP-статус, длительность, разрешённый код ошибки и Retry-After. `status: 0` означает отсутствие зафиксированного HTTP-статуса, а не ответ сервера «0».
- События SSE, попытки переподключения, восстановление сохранённого входа, обновления токена и прекращение сессии. Тела запросов/ответов и все заголовки исключены.

В журнал не попадают тексты сообщений и шаблонов, поисковые запросы и значения полей, имена и ID аккаунтов/каналов/шаблонов, токены, cookies, URL подтверждения входа и произвольные тексты исключений. Значения проходят разрешающий список **до** сохранения, а загруженная история проверяется повторно. Старый экранный отладчик остаётся отдельной функцией; его свободный текстовый отчёт не копируется в новый файл.

## Как читать потерю входа

Смотрите события перед переходом `panel.state` в `error`:

| Событие / код | Что известно из клиента |
| --- | --- |
| `auth.logout`, `reason: user` | Запрошен выход через плагин |
| `reason: discord_logout` | Discord прислал событие выхода |
| `reason: account_changed` | Изменился текущий аккаунт Discord |
| `session_revoked` | Панель сообщила об отзыве сессии |
| `auth.refresh`, `outcome: failure` | Не удалось обновить токен; рядом исходный код/статус |
| `refresh_uncertain` | Клиент не может безопасно повторить обмен одноразового refresh-token |
| `network_error`, `timeout`, `request_timeout` | Сетевой отказ или истечение ожидания; соседние события показывают повтор/прекращение сессии |
| `upgrade_required` | Минимальная версия API выше версии плагина |
| `auth.restore`, `reason: invalid_saved_session` | Сохранённая запись не прошла проверку; её содержимое не журналируется |

Одна запись не доказывает ошибку пользователя или сервера. Например, причина отзыва сессии внутри сервера может потребовать серверного журнала. Отсутствие `runtime.stop` перед следующим `runtime.start` может означать оборванную работу, но не доказывает падение Discord.

## Ограничения

Хранятся последние **2 000 событий**, компактный локальный журнал ограничен **512 КиБ**, старые события вытесняются; `dropped` показывает число вытеснений по размеру/количеству. При экспорте/чтении отбрасывается история старше 24 часов. Форматированный JSON с текущим снимком может быть больше компактного хранилища. Это не полный сетевой перехват Discord и не бесконечный архив всей работы.

Обычные события сохраняются пачкой максимум раз в пять секунд, ошибки авторизации — сразу. При аварийном завершении процесса могут потеряться последние пять секунд обычных событий. При отказе локального хранилища показано предупреждение: файл нужно скачать до перезапуска. Запись автоматически выключается через 24 часа после включения.

В служебном Settings BetterDiscord больше нет копии редактора шаблонов. Кнопка перехода предлагает нажать штатную **Done / Готово**, затем открывает SupportTemplates: это сохраняет совместимость с фокусом нативного модального окна. Экранная отладка свёрнута отдельно и не требуется для файловой записи.
