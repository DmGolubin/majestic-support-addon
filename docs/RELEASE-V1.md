# Первый рабочий выпуск

Решение владельца от 18.10.2026. Ограниченный выпуск с последующим расширением через GitHub Releases. Это план реализации, не заявление о готовом продукте. Ориентир 2–4 дня предварительный; после аудита и прототипа установки пересмотреть по фактам.

## Обязательное для выпуска

- Открытая сборка на основе Vencord с одним SupportTemplates. Используемый исходный коммит основы фиксирован, лицензии и авторство сохранены.
- Windows Discord Stable: ZIP, читаемый .bat и локальный PowerShell; установка, repair, удаление и откат. Не перезаписывать существующий Vencord/BD.
- Настоящий вход по переданному контракту, отмена, refresh, безопасное хранение, выход и отзыв доступа. Без защищённого хранения явно обозначать ограниченную сессию, не сохранять токены в обычных настройках.
- Чтение актуального FAQ и личной библиотеки, поиск, предпросмотр, переменные и корректная вставка. HTML FAQ преобразуется в безопасный текст; не исполняется.
- SSE, восстановление и freshness перед вставкой, смена аккаунта/прав без возврата старых ответов. Локальная библиотека и демовход не должны обходить production-права.
- Проверка GitHub Release, предложение обновления и явное согласие. Применение после закрытия/перезапуска Discord; резервная рабочая версия и rollback.
- Приёмка на настоящем тестовом API и целевом Discord; документированная матрица проверок и ограничения.

## Следующие версии

Личный CRUD/папки/цвета с конфликтами и корзиной; API-напоминания и подбор шаблонов; BetterDiscord-адаптер; оставшиеся улучшения roadmap. Готовый локальный редактор не показывать как синхронизированный: до CRUD в сетевой версии управление выполняется на сайте. Обычный Vencord-адаптер сохраняется.

## Обновление кода

1. Коммит и push сами по себе не затрагивают сотрудников.
2. После проверки публикуется versioned GitHub Release с соответствующим исходным коммитом, списком изменений и готовым пакетом. Репозиторий/канал и ключ проверки фиксируются доверенной сборкой; FAQ не может задавать URL исполняемого кода.
3. Клиент проверяет версию, платформу и совместимость. До согласия сотрудника код не заменяется.
4. Пакет скачивается в отдельный временный каталог, проверяется происхождение/целостность, состав и пути архива. Одна контрольная сумма рядом с архивом не заменяет подпись с закреплённым ключом.
5. Замена атомарная, с журналом состояния и проверенной предыдущей версией. Сбой загрузки, проверки или применения оставляет прежнюю сборку. Повторный запуск завершает либо откатывает прерванную операцию.
6. После закрытия/перезапуска запускается новая версия; при неудачном старте доступно восстановление. Обычный Discord должен оставаться запускаемым без плагина.

Отдельно проверить обновление самого загрузчика и переход версии Discord. Не скачивать/исполнять удалённый скрипт через произвольную команду. Установщик не меняет глобальную PowerShell ExecutionPolicy и не требует администратора для поддерживаемой пользовательской установки. Существующий upstream updater Vencord нельзя оставлять направленным на обычные пакеты Vencord.

## Перед публичным релизом

Разделить настройки и пути форка от обычного Vencord, исключить двойную загрузку и ненужные плагины, проверить зависимости реально поставляемого пакета, отсутствие секретов и приватных исходных материалов в публикуемой истории. Раскрытие исходников разрешено владельцем, но публикация всего текущего репозитория без проверки не является готовым шагом релиза. Публикацию и установку не считать выполненными по результатам тестов ядра.
