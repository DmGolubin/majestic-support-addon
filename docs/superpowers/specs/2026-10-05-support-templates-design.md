# SupportTemplates — шаблоны ответов поддержки в Discord

Дата: 05.10.2026. Автор решений: Oblako. Статус: дизайн согласован в чате, спек на ревью.

## 1. Зачем

Саппорты Majestic RP и Россия Онлайн отвечают в тикетах Discord готовыми шаблонами. Сейчас для этого
есть BetterDiscord-плагин SupportTemplates 0.5.1 (тот же код, что в репо
`persephonemajestic/BetterDiscord-SupportMajestic`). Шаблоны в нём зашиты у каждого свои, есть баги
вставки, и ничего не стоит ответить шаблоном чужого проекта.

Новый плагин:

- работает в BetterDiscord и в Vencord — каждый саппорт ставит тот, что у него;
- берёт командные шаблоны из панели (`panel.majestic-rp.tech`, раздел FAQ) и личные шаблоны
  сотрудника (раздел «Шаблоны»), синхронизирует личные в обе стороны;
- доступ — по входу в аккаунт панели: отозвали доступ в панели — плагин пуст;
- сам понимает проект по серверу Discord и не даёт вставить шаблон чужого проекта;
- выглядит как продолжение панели.

Кто пользуется: сеньоры и уверенные саппорты знают нужный шаблон сразу (нужна скорость), часть
саппортов сомневается (нужно видеть текст целиком), иногда ответ собирают из нескольких кусков.

### Не делаем

- Majestic EU (gta5majestic.com, pl/de) — только ru (Majestic) и ro (Россия Онлайн).
- Авто-отправку: флаг `auto_send` из панели игнорируется, плагин только вставляет текст.
- Запись счётчика использования в панель.
- Защиту чужих тикетов от `/tt` — отдельный модуль, см. `TODO.md`.
- Любую автоматическую отправку сообщений и команд.

## 2. Архитектура

Три слоя. BD- и Vencord-версии отличаются только обёрткой.

```
core/        чистый TypeScript, без Discord и DOM — тестируется отдельно
  model      Template, Project, Category, Status, токены, граница приветствия
  search     поиск и ранжирование
  tokens     разбор и подстановка токенов панели
  guard      определение проекта, зеркала, проверка текста
  compose    сборка ответа из кусков
  source     интерфейс источника данных + LocalSource + PanelSource
ui/          React-компоненты (общие для обеих платформ, получают React и примитивы через адаптер)
platform/
  vencord/   userplugin: ChatBar API, insertTextIntoChatInputBox, DataStore, stores
  bd/        один .plugin.js: BdApi.React, BdApi.Webpack (ComponentDispatch, stores), BdApi.Data
```

Сборка: один репозиторий `support-templates`. Vencord-версия — папка, которая копируется в
`Vencord/src/userplugins/supportTemplates` (Vencord собирают из исходников). BD-версия собирается
бандлером в один файл `SupportTemplates.plugin.js`, который кладут в папку plugins.

Адаптер платформы отдаёт ядру и UI: `React`, `insertText(text)`, `currentGuildId()`,
`currentChannelId()`, `storage` (get/set), `toast`, `openModal`, `subscribeChannelChange`.

Вставка в обеих версиях — одним вызовом `ComponentDispatch.dispatchToLastSubscribed("INSERT_TEXT")`
(в Vencord через `insertTextIntoChatInputBox`). Никакого `execCommand` и синтетического paste:
именно перебор способов в 0.5.1 давал «призрачный» текст, который не удаляется (баг 1).

## 3. Данные

### Модель шаблона (ядро)

| Поле | Командный (FAQ) | Личный | Локальный (импорт) |
|---|---|---|---|
| id | `faq:<id>` | `tpl:<id>` | `local:<group>||<title>` |
| project | регион выборки: ru → Majestic, ro → Россия Онлайн | по папке (домены папки) или «любой» | `## группа` |
| title | `title` | `name` | `### заголовок` |
| text | `content` | `text` | тело |
| category | `category` | папка | — |
| status | `actual` / `needs_review` / `outdated` + `status_note` | — | — |
| teamUses | `usage_count` | — | — |
| command | — | `shortcut` | — |
| color | — | `color` | — |
| updatedAt | `updated_at` | `updated_at` | — |
| readOnly | да | нет | да (правится в настройках) |

Граница приветствия — маркер панели `[[greeting:end]]`: текст до него — приветствие,
«без приветствия» отрезает его вместе с маркером. В обычной вставке маркер убирается.

### Источники

- **LocalSource** — работает сразу, без панели. Импорт `SupportTemplates.config.json` из BD 0.5.1
  (raw, usage, pinned → избранное, binds), текстового формата `## проект / ### шаблон` и JSON-массива.
  Хранится в хранилище плагина.
- **PanelSource** — включается после входа (раздел 9). Командные шаблоны ru и ro, личные шаблоны,
  папки, избранное.

UI не знает, откуда шаблон. Если вошёл в панель, локальные шаблоны остаются отдельной группой
«Локальные» (для миграции), их можно перенести в личные одной кнопкой.

## 4. Защита проекта

Проект определяется по ID сервера Discord. По умолчанию зашито:

| Guild ID | Проект | Регион FAQ |
|---|---|---|
| `530693013622489088` | Majestic RP | ru |
| `1089530150540034181` | Россия Онлайн | ro |

Позже эту таблицу может отдавать панель.

На любом другом сервере (рабочий сервер саппортов, ЛС) плагин один раз спрашивает: «Это сервер
какого проекта? Majestic / Россия Онлайн / Ни того ни другого — выбирать при открытии». Ответ
запоминается. Пока проект не выбран, не вставляется ни один проектный шаблон — ни из окна, ни
через `;`, ни по Alt+N. Личные шаблоны без проекта вставляются везде.

Правила:

1. На сервере проекта видны только его шаблоны и личные. Шаблоны другого проекта — только через
   явное «Показать шаблоны другого проекта».
2. **Автоподбор зеркала.** Выбран шаблон чужого проекта — ищем шаблон текущего проекта с тем же
   названием (нормализация: регистр, ё/е, пробелы, пунктуация). Нашёлся — вставляем его и
   показываем «Вставлен вариант для Majestic». Нет пары — блок с объяснением и отдельным окном
   «Да, вставить шаблон Россия Онлайн».
3. **Проверка текста** (для личных и локальных): перед вставкой ищем в тексте признаки чужого
   проекта — домены (`majestic-rp.ru`, `gta5majestic.com`, `forum.russia.online`, `russia.online`),
   названия проектов и лаунчеров. Нашли — предупреждение. Шаблон можно один раз пометить «упоминает
   другой проект намеренно» (пример: «Удаление кэша Majestic RP» в наборе РО) — больше не спрашиваем.
4. Сборка ответа принимает куски только текущего проекта, чужой проходит через автоподбор.

## 5. Интерфейс

### Стиль — как панель Majestic

Палитра `.dark` панели: фон `hsl(216 16% 6%)`, карточки `hsl(218 17% 9%)`, рамки `hsl(215 16% 15%)`,
приглушённый текст `hsl(214 10% 80%)`, основной `hsl(216 10% 91%)`, акцент `hsl(342 77% 44%)`,
фокус `hsl(342 80% 56%)`, радиус 6–12px, шрифт Golos Text → Inter → системный. Из базы знаний:
янтарная линия у заголовка (`#e0a83f`), капс-подписи секций, каллауты (красный `#ef456e` — риск,
зелёный `#6aa84f` — норма, янтарный — контекст, синий `#4a90d9` — запросить). Подсветка совпадений
поиска — янтарь на тёмном (`#211b10` / `#f1c46f`).

Проекты различаются **иконками** в одинаковых квадратных ячейках, не цветом (фирменные `#d00457`
и `#c23533` слишком близки): Majestic — фавикон `masterlist.majestic-rp.ru/favicon.majestic.png`,
Россия Онлайн — логотип-ушанка с `russia.online`, вписанный в квадрат на тёмной подложке. Иконки
вшиты в плагин (PNG), внешних запросов за ними нет. Прочих SVG-иконок в интерфейсе нет.

Мокапы: `.superpowers/brainstorm/189-1791216255/content/concept.html` (в рабочей папке
Majestic RP).

### Четыре состояния

**А. Команда в строке ввода.** Набираешь `;` + слово (`;снр`) — над полем всплывают подсказки как у
слэш-команд Discord: до 6 шаблонов текущего проекта и личных. Это быстрый поиск: точное совпадение с
командой личного шаблона — первым, дальше поиск по названию, синонимам, тексту. Tab/Enter — заменить
`;снр` текстом шаблона, Shift+Tab — без приветствия, ↑↓ — выбор, Esc — убрать подсказки
(`;снр` остаётся обычным текстом). Префикс по умолчанию `;`, меняется на `.` `,` `!` (`/` нельзя —
это слэш-команды Discord). Срабатывает только в начале строки или после пробела.

**Б. Окно над строкой ввода** (кнопка в строке ввода или Ctrl+Alt+T). Слева: поиск, вкладки
проекта (только текущий) и «Мои», разделы ★ Избранное → Недавние (метки «обновлён», «новый») →
категории команды (Частые проблемы, Навигация…). У строки: иконка проекта, название, метка статуса
(«устарел» / «на проверке»), Alt-клавиша для избранного. Справа — панель текста, раскрывается по →
и запоминается у каждого: заголовок с янтарной линией, «Частые проблемы · команда использовала
2627 раз · обновлён 03.10», текст с видимой границей приветствия, кнопки «Вставить», «Без
приветствия», «+ в ответ», «★». Без входа в панель — пустые разделы Избранное/Недавние
заменяются локальными закреплёнными.

**В. Защита и поля.** Перед вставкой шаблона со статусом `outdated`/`needs_review` — красный
каллаут «Шаблон помечен «Устарело». Комментарий… Проверьте текст» и кнопки «Вставить всё равно» /
«Предложить правку» / «Отмена». Если в тексте есть токены-поля — форма заполнения до вставки
(раздел 7).

**Г. Личные шаблоны** («Мои» или Ctrl+N). Большое окно: слева папки (личные + категории команды
только для чтения), справа редактор: название, команда, папка, цвет, текст с подсказкой токенов,
«Сохранить», «Дублировать», «В корзину» (корзина панели, 7 дней), метка «синхронизировано с
панелью · 19:24». Командные шаблоны здесь только читаются; «Предложить правку» уходит в
предложения FAQ панели.

## 6. Поиск и ранжирование

Перенос логики из VK-скрипта `VKMaj.js`:

- нормализация: регистр, ё→е, неразрывные пробелы, токены `{…}` выбрасываются;
- уровни совпадения: все слова в названии (4) → в названии + синонимах (3) → все слова длиной ≥3 в
  тексте (2) → нечёткое одно слово ≥4 символов, плотная подпоследовательность в названии (1);
  нечёткий проход только если строгих совпадений нет, счётчик тогда с «≈»;
- синонимы — таблица из `VKMaj.js` (`фпс` → «Фризит игру», `снр` → «Server not responding», …),
  хранится в ядре и расширяется;
- неверная раскладка: если пусто — повтор в другой раскладке, подпись «Раскладка: показаны
  результаты для …»;
- превью строки — строка текста с максимумом попаданий, а не начало шаблона;
- порядок без запроса: Избранное (в своём порядке) → Недавние → по личной частоте → по `teamUses`;
  при запросе: уровень совпадения, затем бонусы за избранное и частоту.

## 7. Вставка

Конвейер одного шаблона:

1. Защита проекта (раздел 4).
2. Статус устарел / на проверке → подтверждение (состояние В).
3. Токены. Поддерживаются как в панели: `{|}` — курсор, `{{поле}}` — поле ввода,
   `{{поле|a|b}}` — выбор из вариантов, `{{date}}` / `{{date+3d}}` / `{{time+30m}}` — дата/время со
   сдвигом, буфер обмена, выделенный текст (в Discord — выделение в сообщениях перед открытием окна),
   ссылка/заголовок (в Discord — ссылка на канал и его название). Есть поля → форма, иначе сразу.
4. Граница приветствия: обычная вставка — маркер удаляется; «без приветствия» — отрезается всё до
   маркера.
5. Вставка в позицию курсора одним `INSERT_TEXT`. Отправки нет никогда. Курсор `{|}` — после
   вставки ставится в отмеченное место, если редактор это позволяет; иначе маркер просто убирается.
6. Личная статистика и «Недавние» обновляются локально.

### Сборка ответа

«+ в ответ» (кнопка, Shift+Enter в окне) кладёт кусок в полоску над строкой ввода:
«Ответ: Соединение · Логи · + ещё… → Вставить всё». Куски переставляются перетаскиванием,
удаляются крестиком. «Вставить всё»: приветствие сохраняется только у первого куска, у остальных
отрезается по границе приветствия, куски склеиваются пустой строкой, проходят конвейер (поля
спрашиваются одной формой). Смена канала очищает полоску.

## 8. Клавиатура

| Где | Клавиши | Действие |
|---|---|---|
| везде | Ctrl+Alt+T | открыть/закрыть окно |
| везде | Alt+1…9 | вставить 1–9-й шаблон Избранного текущего проекта (фиксированный порядок) |
| везде | свой бинд | вставить привязанный шаблон |
| окно | ↑↓, Enter | выбор, вставка |
| окно | → / ← | показать / скрыть текст |
| окно | Alt+1…9 | вставить видимую строку |
| окно | Ctrl+D | в избранное / из избранного |
| окно | Shift+Enter | + в ответ |
| окно | Ctrl+N | новый личный шаблон |
| окно | Esc | очистить поиск, затем закрыть |
| ввод | `;слово` + Tab | состояние А |

Удержание клавиши не повторяет вставку (`e.repeat` игнорируется) — баг 0.5.1. Свои бинды
назначаются из контекстного меню шаблона (ПКМ → «Назначить клавишу»), кнопки в строке нет (баг 2,
миссклик). Бинды и раскрытость панели текста — локальные. Сочетания копирования/вставки/отмены и
Ctrl+Alt+T/Alt+1…9 назначить нельзя.

## 9. Вход и синхронизация

**Вход.** «Войти через панель» в настройках. Способ выбирает разработчик панели:
OAuth-окно Discord для приложения панели внутри клиента или страница панели в браузере с
подтверждением. Итог — **токен устройства**; плагин появляется в разделе устройств панели и
отзывается там. Discord-токен пользователя никуда не передаётся. Токен лежит в хранилище плагина
на этом ПК, в экспорт/бэкап не попадает.

| Данные | Направление | Когда |
|---|---|---|
| FAQ ru и ro | панель → плагин | запуск, каждые 15 мин, «Обновить» |
| Личные шаблоны и папки | обе стороны | сразу после правки + те же интервалы |
| Избранное | обе стороны | сразу после изменения |
| Настройки расширения (префикс) | панель → плагин | при синхронизации |
| Бинды, сборка ответа, раскрытость, привязки серверов | только локально | — |

**Кэш.** Последняя копия хранится локально; панель недоступна — работаем с ней и показываем
«данные от 14:20». Правки личных шаблонов без связи — в очередь, уходят при восстановлении.
**Конфликт:** побеждает последняя правка, перезаписанная версия уходит в корзину панели.
**Отзыв:** ответ 401/403 → стереть токен, кэш FAQ и личных, показать «Доступ отозван — войдите
снова». Локальные импортированные шаблоны остаются.

**Обновления плагина** раздаёт панель: плагин по токену устройства проверяет версию, BD-версия
скачивает новый `.plugin.js`, Vencord-версия получает архив папки плагина и подсказку пересобрать.

## 11. Ошибки

- Discord поменял внутренности (не нашёлся ComponentDispatch, store) — плагин не падает: кнопка
  неактивна с подсказкой, текст шаблона копируется в буфер с тостом «Вставьте Ctrl+V».
- Панель недоступна — кэш + метка возраста; нет кэша — локальные шаблоны и баннер «Нет связи с
  панелью».
- Невалидный импорт — предпросмотр «найдено N шаблонов / не распознано» до замены, как в панели.
- Ошибки пишутся в консоль с префиксом `[SupportTemplates]`; в настройках «Скопировать отчёт»
  (версия, платформа, источник, число шаблонов, последние ошибки) — для багрепорта.
- Окно и полоска обёрнуты в ErrorBoundary: ошибка UI не ломает строку ввода Discord.

## 12. Тестирование

- **Ядро — автотесты** (Vitest): разбор форматов импорта на реальном `SupportTemplates.config.json`
  (133 шаблона, 2 проекта), поиск (синонимы, раскладка, нечёткий, уровни), ранжирование, токены
  (каждый вид, сдвиги дат), граница приветствия, сборка ответа, автоподбор зеркал (все пары MJ↔RO
  из конфига), проверка текста на чужой проект.
- **Источник панели** — тесты на записанных ответах API (фикстуры без личных данных): кэш, очередь,
  конфликт, 401.
- **Платформы — чек-лист в живом Discord** (BD и Vencord): кнопка в строке ввода, Ctrl+Alt+T,
  `;снр`+Tab, Alt+N с зажатием, вставка длинного шаблона и стирание Backspace, переключение
  Маджа↔РО↔чужой сервер, автоподбор зеркала, устаревший шаблон, форма полей, сборка ответа,
