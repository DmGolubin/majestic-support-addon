# A29 / A30 / D17 — уведомления, BetterDiscord и доставка

## Согласованный объём

- Уведомления личных тикетов различаются для Majestic и РО; нажатие открывает конкретный доступный тикет. Без отправки сообщений и без вычисления Discord channel ID из числового ID тикета панели.
- Host-настройки используют оформление Discord, без лишней карточки «Подключение». Единая подпись `SupportTemplates · Версия <полная версия>`.
- Проверка задержек BetterDiscord при перетаскивании и вставке; пользователь разрешил использовать Canary для тестов. Stable не затрагивается.
- Два формата для сотрудников: BetterDiscord plugin.js и Lite + SupportTemplates с отдельным payload и GUI, запускаемым BAT. Пользователь явно выбрал Lite, полный Vencord остаётся личной сборкой.
- Публикация в `DmGolubin/majestic-support-addon`. На старте репозиторий пустой, приватный, доступ WRITE; видимость не меняется. Доступ к анонимным автообновлениям требует публичного репозитория и опубликованного выпуска.
- Изменение порогов Discord отдельно от Telegram ожидает решения/API Дмитрия и не входит в текущие правки.
- Последнее уточнение владельца: новые тикеты остаются только со звуком, без карточек и toast.

## Проверки и результат

### Интерфейс и навигация

Карточки личных напоминаний используют название/иконку проекта, малиновый акцент Majestic и синий РО. Перед переходом выполняются свежая проверка назначения, проверка исходных project/ticket/waitingCycle/reminder/guild/channel и Discord VIEW_CHANNEL. При отсутствии mapping API кнопка перехода не появляется. Preview отдельно для каждого проекта не вызывает API, звук или receipt.

На независимом review исправлена преждевременная отмена карточки при обычном polling: playback guard привязан к одному snapshot, а доставленная карточка сохраняется до 45 секунд с отдельными session/settings guards. Проверка назначения на нажатии остаётся обязательной.

Браузерный прогон `scripts/qa/runs/a29-ui/final-03/regression.json`: 197 проверок, 0 ошибок, размеры 900×720 и 360×640, 32 снимка; исходники UI не менялись в прогоне. Границы API, навигации и аудио в этом прогоне замоканы.

В реальном BetterDiscord Canary проверены обе preview-карточки и подпись `SupportTemplates · Версия 1.0.1-canary.37`. Снимки и результат: `scripts/qa/runs/a29-live-preview*.png`, `a29-live-preview.json`. Настоящее наступление срока назначенного тикета и слышимость требуют отдельной пользовательской приёмки.

### BetterDiscord

Canary временно переключён с Lite .36 на установленный BD 1.14.3; штатный Discord с полным Vencord не изменялся. Перед переключением сохранены загрузчик, оригинальный ASAR, конфигурация и предыдущий BD plugin. Владелец самостоятельно вошёл в отдельный профиль BD.

На реальном редакторе Discord, 68 шаблонов, три вставки без отправки сообщений:

| Сборка | От обработчика клика до кадра с текстом |
| --- | --- |
| .36 baseline | 46.6 / 16.6 / 26.1 мс |
| .37 candidate | 30.4 / 20.8 / 15.6 мс |

Исходный пустой черновик восстановлен после каждой вставки. Заявленные 3–4 секунды на прогретом соединении не воспроизвелись; это не доказательство отсутствия задержки при восстановлении связи.

Одинаковое перетаскивание в реальном BD: максимальный интервал кадра 183.6 → 67.3 мс, p95 21 → 20.9 мс, зарегистрированные long tasks 3 → 0. Положение восстановлено через Escape. Это короткие наблюдения одного клиента, а не универсальная гарантия FPS.

В исходниках обновления позиции объединены через requestAnimationFrame, элементы строк переиспользуются. Изолированная фикстура 1000 шаблонов: 240 → 60 обновлений, 240000 → 0 пересозданных строк; 124 → 9.5 мс без layout/paint.

Дополнительно убраны повторные переходы через BD bridge для чистых операций с путями (561 → 9 в фикстуре) и stat-предикатов; сами filesystem-проверки не кешируются. События долгих кадров и замеры производительности сохраняются вместе с обычными событиями, экспортом или остановкой, но больше не запускают циклическую цепочку «запись → долгий кадр → запись». Buffer поддерживает обе реальные формы экспорта: Node `{ Buffer }` и прямой конструктор в BD. Nonce создаётся Web Crypto.

Полный тест обнаружил неточность сравнения больших NTFS inode: числовое округление могло подтвердить чужую папку. Теперь неоднозначные ID проверяются bigint-stat, а bridge без точных ID требует совпадения канонических путей. Проверен настоящий MSIX-каталог: физический LocalCache и main.log доступны.

Финальный native-кандидат BD действительно дописывает main.log, `deliveryLost=0`; «Открыть папку логов» открыл правильный каталог Explorer. **Сохраняется прежнее ограничение:** `window.localStorage` в этом renderer отсутствует, поэтому дополнительная резервная копия в localStorage недоступна и интерфейс честно показывает предупреждение. Основной файл работает. Переход резервной копии на отдельное асинхронное хранилище требует отдельной реализации.

### Установщик

BAT без аргументов открывает WPF GUI; с аргументами сохраняет CLI. `payload/` отделён от GUI. Доступны Stable/Canary без выбора по умолчанию, установка/обновление, статус, восстановление и удаление. Все операции используют прежний backend с ownership/hash/process checks. Процесс работает асинхронно, индикатор не изображает выдуманный процент.

Проверены 51 группа TEMP-сценариев установщика, GUI-группы, 11 updater-проверок и WPF-рендер при 96/120 DPI. На review исправлен приоритет Pending над Installed: незавершённое обновление теперь показывает предупреждение и раскрывает подробности. Реальный обработчик дополнительно проверен 5 сценариями.

### Финальная проверка и доставка .37

Исходники собраны из `ab04485f0957adef867fab93d86718cdc16718ed` и отправлены в `main` репозитория `DmGolubin/majestic-support-addon`. Загружены все 8 файлов [черновика prerelease 1.0.1-canary.37](https://github.com/DmGolubin/majestic-support-addon/releases/tag/untagged-146e0fe1447163da1f14): отдельный BD plugin, BD ZIP, Lite ZIP, исходники, инструкция, манифест обновления, SHA256SUMS и build evidence. Репозиторий остаётся приватным, выпуск — черновиком; анонимная доставка обновлений пока недоступна.

После последних изменений прошли:

- 2479 тестов в 135 файлах; обе проверки типов.
- 33 проверки финальных пакетов и 13 проверок точного BD runtime.
- Установка, статус и удаление настоящего упакованного Lite payload в TEMP.
- Проверка восьми файлов выпуска и совпадение SHA-256 установленного BD plugin с загруженным: `ae12ebf11b216116d0699d8cefadeb4d18b6c158b2a72852b47c7129129fce8d`.

Повторная проверка точного релизного файла уточняет раннее сравнение производительности. В первом прогоне изменение DOM заняло 10–16 мс, следующий кадр — 988–1062 мс, полное действие Playwright — около 3 с. Причина различия времён не доказана: полное действие включает ожидания автоматизации. После явного вывода Canary на передний план (`visible`, `focused=true`) три вставки дали DOM 20.1 / 378.5 / 10.2 мс, следующий кадр 25.8 / 380.5 / 13 мс, полное действие 152 / 429 / 121 мс. В обоих прогонах отправки не было и исходный пустой черновик восстановлен. Результаты: `a30-insert-release37.json` и `a30-insert-release37-foreground.json` в `scripts/qa/runs/`.

Повторное перетаскивание релизной .37: p95 21 мс, максимум 195.9 мс, long tasks 199 / 172 / 165 мс (`a30-drag-release37.json`). Поэтому раннее уменьшение максимума 183.6 → 67.3 мс не считается устойчивым устранением зависаний. RAF/мемоизация и сокращение bridge-вызовов реализованы, но отдельные длинные кадры сохраняются; требуется пользовательская приёмка и при повторении задержки — профиль конкретного эпизода.

Canary оставлен с BetterDiscord 1.14.3 и точной .37; Lite .37 доступен отдельным пакетом. После проверок Canary перезапущен обычным способом: отладочных аргументов и слушателя 35937 нет, подключение плагина `ready`. Stable не менялся. Основной журнал после перезапуска вырос до 690666 байт, исходный префикс сохранён побайтно, `deliveryLost` остался 0. Предупреждение о недоступной дополнительной резервной копии localStorage сохраняется; основной main.log исправен.

Оставшаяся приёмка: реальное просроченное назначение с переходом из карточки, слышимость звука, субъективная плавность BD и установка GUI на рабочем месте сотрудника. Живые preview и TEMP-сценарии не подменяют эти проверки.
