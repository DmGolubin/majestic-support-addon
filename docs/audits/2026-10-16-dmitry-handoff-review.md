# Перепроверка единого файла Дмитрию

Дата: 16.10.2026. Объект: docs/DMITRY-API-HANDOFF.md. Проверены все разделы, примеры и таблица приёмки.

Основание: решения владельца в переписке, последнее уточнение двух систем уведомлений, существующий контракт API 1.1. Device-code flow дополнительно сверен с RFC 8628: https://www.rfc-editor.org/rfc/rfc8628 . Серверные исходники и действующее API не проверялись; документ этого не утверждает.

Исправлено:
- Убрано общее утверждение, будто каждая техническая деталь уже согласована.
- Один общий порог с отдельными каналами доставки отмечен предложением; устранён конфликт с отдельным порогом Discord.
- Источник данных Telegram в БД учтён во вступлении. Сохранены пользовательские правила Discord 20/30.
- Дедупликация по циклу не навязывает запрет повторов существующей системы; нужен ключ конкретного напоминания.
- API может отдавать готовые события существующего сервиса либо состояние; оба варианта сразу не требуются.
- Отзыв сессии не запускает новую загрузку библиотеки.
- Оценка нагрузки явно учитывает дополнительные запросы тикетов отдельно.
- Публичное начало входа, секретный обмен кодом и refresh отделены от рабочих запросов с access-токеном.
- Сроки, корзина, HTTP-контракт и схема настроек обозначены техническими предложениями. Пограничные случаи оставлены вопросами, а не придуманными ответами.

Проверены JSON-примеры, блоки Markdown и отсутствие старых конфликтующих формулировок. Исходники плагина не менялись, тесты кода не запускались. Файл готов к передаче для согласования и реализации; это не подтверждение готовности production API.
