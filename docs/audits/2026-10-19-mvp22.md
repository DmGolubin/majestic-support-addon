# MVP polish: three distributions, UI and panel traffic

## Scope

Q17 implements the owner's request to polish existing features in BetterDiscord,
full Vencord and the reduced Vencord-based distribution. No new product features.
Local packages target `1.0.1-canary.22`. Installed Discord clients and published
GitHub releases are not modified by this audit.

## Login destination and domain boundaries

Device authorization responses are validated before a browser link is constructed.
Both the current panel origin and the legacy production login origin remain
accepted response inputs, but the browser destination is always
`https://panel.majestic-rp.tech/connect?code=<encoded user code>` in production.
Missing complete links and legacy `user_code` parameters are normalized too.
Unexpected origins, paths, credentials, fragments, extra or duplicate query
parameters remain rejected. The secret device code is never used in the link.

Regression evidence: five new expectations failed before the change; the four
protocol/client/transport/events suites then passed 311 tests. Raw results are in
`scripts/qa/runs/mvp22/connect-red.log` and `connect-green.log`.

| Destination | Purpose and boundary |
| --- | --- |
| `panel.majestic-rp.tech/api/plugin/v1/*` | Fixed production API and event stream; bounded requests, no cookies or redirects. |
| `panel.majestic-rp.tech/connect?code=…` | Browser confirmation; only the public user code goes in the link. |
| `majestic-rp.tech/connect` | Legacy API response compatibility; no longer opened by the plugin. |
| `discord.com`, `ptb.discord.com`, `canary.discord.com` | Discord host identity/vault boundaries; account changes still invalidate the previous account's data. |
| `cdn.discordapp.com/icons/*` | Existing server icons; known server IDs and validated icon hashes. |
| `api.github.com/repos/skyjacc/support-templates/releases` | Update discovery, at most three pages per check; six-hour automatic interval. |
| GitHub release assets/CDNs | Repository-bound asset URLs, bounded redirects/downloads and hash verification before apply. |
| `127.0.0.1:47833` | Explicit developer demo only; not the production panel endpoint. |

The updater transport allows only its GitHub release CDN hosts:
`release-assets.githubusercontent.com`, `objects.githubusercontent.com` and
`github-releases.githubusercontent.com`. Native origin gates continue to accept
only the three supported Discord origins. No permissive origin fallback was added.

An unauthenticated, low-volume probe returned HTTP 200 without a Location header
from both bare `/connect` URLs, and HTTP 401 from `/me` and `/snapshot` as expected.
A separate fresh Chromium navigation encountered a transient HTTP 502 from the
canonical URL. Navigating the legacy origin loaded its application and then
redirected to the panel; the unauthenticated panel subsequently initiated Discord
OAuth. These observations distinguish the unnecessary legacy-domain hop, which
the plugin now removes, from authentication redirects controlled by the website.
They do not prove an authenticated login round-trip or diagnose the upstream 502.

Evidence: `scripts/qa/runs/mvp22/domains.json` and `connect-browser.json`.
No user credentials, cookies or Authorization headers were supplied or recorded.

## Request/session fixes

- Coalesce synchronous SSE change bursts before beginning a resync. Catalog
  invalidation remains immediate, so stale permissions cannot be used meanwhile.
- Retain network/rate-limit backoff even when the in-flight read has been
  superseded by an SSE event. Focus, manual reload and new events cannot bypass it.
- Initial parallel profile/snapshot failures use the longer Retry-After value.
- Very long Retry-After values use bounded timer chunks and retain their deadline.
- Treat a generic `transport_error` as transient rather than cancelling the session.
- Reminder invalidation retains the polling pause after network failure.
- Notification-settings reads honor Retry-After; HTTP 429 without it defers reads
  for 60 seconds. Repeated settings synchronization shares that delay.

New regression tests execute real controller/client modules with mocked transport
or Discord host boundaries. Durations below use fake clocks, not hours of live
Discord use and not a load test of the production service.

| Scenario | Verified request budget |
| --- | --- |
| Six hours of healthy idle, deterministic jitter | 361 `/me` + `/snapshot` pairs including startup; one SSE connection. |
| 100 simultaneous explicit reloads | One profile/snapshot pair. |
| 100 synchronous SSE changes | Three GETs before the fix, two after. |
| Superseded 429/503 with 120-second Retry-After | No further GET before the deadline, including focus/reload events. |
| Five offline minutes | Six failed reads; next successful attempt restores the library. |
| Repeated short SSE EOF/errors | Reconnect delays 2, 4, 8, 16 seconds with deterministic jitter. |
| Six hours with real PanelClient and mocked tokens/transport | 720 protected reads, exactly 24 durable refresh rotations. |
| 100 concurrent reads and an SSE authorization after 401 | One shared refresh rotation. |
| 100 settings synchronizations after 429 | 101 requests before, one until the deadline after the fix. |

Genuine revocation, account mismatch and identity validation still fail closed.
An uncertain rotating refresh cannot safely be retried with the old refresh token;
it still requires a new login. This audit does not claim that every server-side
logout or backend outage is eliminated.

## UI fixes and source-browser checks

- Picker dismissal restores its opener's focus without taking focus from insertion,
  another dialog or settings.
- Dirty-close confirmation focuses the safe return button. Returning or pressing
  Escape preserves the draft and restores the previously focused control.
- Login keyboard handling ignores IME composition.
- Unbroken error text wraps: an observed 3451px overflow in a 409px settings
  scrollport is now contained at 409px.

162 browser assertions pass. The matrix contains 18 configurations and 90 geometry
assertions: three distribution identities, physical viewports 1200×900/640×480,
effective scale 100/125/150%. Scale is represented by reduced CSS viewport space,
not actual Electron zoom. Settings tabs retain their dimensions and the picker
is clamped to the available viewport. Additional cases exercise keyboard use,
selection in chat, resizing/persistence/cancellation, long titles, empty/loading/
error states, drafts and failed writes. Sixteen BetterDiscord service-page layouts
cover 600/480/384/320px and idle/loading/error/ready states. Current diagnostic
controls cover toggling, clear/cancel, download feedback and button spacing.

Two additional editor checks pass at 427×320 and 1200×900, including a textarea
expanded to 550px. At very short height the existing whole-form scroll intentionally
replaces a sticky footer; both actions remain reachable. At normal height the
footer is outside the body scrollport. The original textarea/footer overlap was
not reproduced. Parent visual review confirmed the narrow action-row screenshot.

Evidence and reusable commands are in `scripts/qa/runs/q17-ui/README-Q17.md`,
`after-03/regression.json`, `after-03/editor-actions.json` and the four checked-in
`scripts/qa/q17-ui-*` scripts. Baseline and intermediate failures are retained.
The UI worker's seven targeted suites pass 127 tests; both typechecks pass.

Browser fixtures execute actual source UI with mocked Discord stores, API,
insertion and diagnostic downloads. They do not verify Discord Slate integration,
native host-modal focus traps, authenticated API or installed packages. No claim
of zero memory growth during a real work shift is made.

## Final integrated verification

Package evidence is added after building the frozen sources. An initial full run
exposed one old test expectation for immediate recovery after an invalidated 503;
it now asserts the required pause and eventual recovery. During concurrent QA,
the DPAPI availability probe failed and the BD build hook timed out. Both passed
unchanged in the subsequent focused 145-test run. The final full run is recorded
separately rather than presenting those initial failures as a clean pass.
