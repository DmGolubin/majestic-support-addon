Четыре параллельных агента: архитектура/состояния, корректность вставки и данных, безопасность входных данных/локальных сервисов, установка/цепочка поставки. После read-only аудита троим выделены непересекающиеся файлы для исправлений. Родитель проверяет baseline, зависимости, сводит результаты и начинает независимые валидаторы production-протокола. Подтверждённые баги отделяются от отсутствующих функций будущего релиза.

## Зависимости основы

Предварительная классификация по dependency paths и импортам, не полный анализ достижимости:

- minimatch, brace-expansion, fast-uri, postcss, js-yaml и ряд остальных — преимущественно ESLint/Stylelint/SVGO и сборочные зависимости. Их надо обновить/исключить в изолированном форке и проверить сборку; не объявлять ошибками работающего чата без доказательства пути исполнения.
- zip-local → jszip используется scripts/build/buildWeb.mjs; это не готовый standalone installer. Не переносить эту старую распаковку в updater.
- monaco-editor → dompurify: Monaco подключён в main/ipcMain.ts для редактора. В урезанной сборке редактор тем не нужен; исключение должно быть подтверждено составом bundle, не только скрытой кнопкой.
- moment находится в dev/type-зависимостях; runtime common/utils.ts получает moment из Discord. Обновление npm-пакета само по себе не обновит Discord-модуль.

Дальнейший выпуск требует аудита зависимостей именно закреплённого форка и итогового bundle. Рабочая установка Vencord не обновлялась и её зависимости автоматически не менялись.

## Архитектурные находки (проверка агента)

1. P1 до production: демоотзыв блокировал вставку, но сохранял каталог и личные записи в памяти/на экране; повторное подключение могло использовать их. Это баг демосессии, не доказательство работающей production-уязвимости. Исправлено в demo.ts: общая очистка сессии, каталога, личных данных и management; поздние ответы отменяются. Локальная библиотека сохранена отдельно.
2. P2: stop вызывал действие выбора локальной библиотеки; повторный start менял режим без решения пользователя. Исправлено: disposeDemo отделён от явного disableDemo.
3. P2: generation вставок использовался как lifecycle startup; изменение сессии во время store.load отменяло монтаж, хотя stop не вызывался. Исправлено в index.tsx: отдельный lifecycle epoch, загрузка realStore; stop по-прежнему запрещает поздний монтаж.
4. P2, осталось (C05): демокаталог идёт через legacy importer с ID от названия. Rename теряет pins/binds. В production использовать server ID и version напрямую, не импорт старого конфига. Демосервер в этом блоке не переделывался.

Обязательные недостающие части: production transport/session, freshness перед одиночной и составной вставкой, безопасное хранилище, проверяемый release/installer. Их отсутствие не выдаётся за исправленную функцию. Root typecheck включает только src/core/tests; адаптер и собранный артефакт должны проверяться отдельно.

## Безопасность данных и локального сервиса

- P2: подбор суффиксов одинаковых названий в импорте был квадратичным. Исправлен nextSuffix-map с сохранением прежних ID и резервированием коллизий. Агент измерил 8 000 одинаковых записей: 11,65 с до и 24 мс после на своей машине; это не универсальная оценка скорости. Тест ограничивает количество обращений к Set, а не время. Ограничение общего размера файла не добавлено: очень большой импорт всё ещё может быть тяжёлым.
- P2: подробный лог мог записать символ/физический код AltGr и клавиши поля password. Исправлены keyFields и keyDesc: password, composition и печатные AltGr/Windows Ctrl+Alt маскируются, включая code. Тесты выполняют настоящие функции диагностики на искусственных событиях.
- P3: loopback roadmap-сервер принимал произвольный Host. Добавлена проверка одного локального Host и допустимого Origin, если он присутствует. GET/HEAD проверены на parser-стенде. Полная атака DNS rebinding в браузере не воспроизводилась. Уже запущенный старый процесс получает исправление только после перезапуска.
- Новый panelProtocol.ts не совершает запросов: проверяет ответы device/token, HTTPS origin, ссылку подтверждения, времена и пути; ошибки не включают секретные значения. `verification_uri_complete` необязателен согласно OpenAPI. Ограничение query-параметра на `user_code` — наша политика до сверки с настоящим ответом, а не подтверждённая серверная гарантия совместимости.
- Узкий поиск характерных секретов в tracked-файлах не нашёл совпадений. Это не полный аудит истории/бинарных материалов перед публикацией. React-вывод шаблонов не показал исполнения произвольного HTML в исследованных путях.

Дополнительные особенности upstream, не новые уязвимости:

- autoUpdate включён по умолчанию. `--standalone` сам по себе не создаёт безопасный отдельный канал релизов и не вырезает плагины. Отключить upstream updater на уровне состава/точек входа; отдельный репозиторий не должен скачивать обычные пакеты Vencord.
