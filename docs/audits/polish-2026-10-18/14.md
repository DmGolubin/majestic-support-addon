## Targeted acceptance scenarios / unverified hypotheses

1. **Dropdown clipping inside the new body scrollport** (potential P2). `src/vencord/ui/settings-layout.css:44` makes the editor body an overflow container, but `src/vencord/ui/Select.tsx:34` measures available room against `.vc-stx-settings`; the absolutely positioned list stays inside the body (`src/vencord/styles.css:373`). At 480×600 or 900×675, with at least ten stub folders, scroll the Project/Folder trigger close to the upper or lower edge of the editor body, then open it and traverse all options with mouse and keyboard. Compare the list bounds to **the body**, not just the settings bounds. Possible consequence: options are clipped or opening scrolls the editor unexpectedly. If reproduced, the minimal fix is to include the nearest editor scrollport in the dropdown's available-space calculation. No DOM geometry was measured here.

2. **Long conflict action stays on one line** (potential P2). `src/vencord/ui/PanelPersonalLibrary.tsx:219` renders “Отменить черновик и открыть текущую запись”; base `.vc-stx-btn` at `src/vencord/styles.css:125` has `white-space: nowrap` and fixed 32px height. The flex note at `src/vencord/ui/panel-personal.css:19` wraps items but does not wrap text inside that button. Use a stub 412 conflict with a current record at 320×640 and 360×640; scroll to conflict controls and compare button right edge to body right edge, and body scrollWidth to clientWidth. Also repeat at 200% zoom with equivalent CSS viewport dimensions. Possible consequence: horizontal scrolling is needed to read/use the full action. If reproduced, locally allow note action text to wrap and use auto height with the existing minimum height. Not counted as a verified finding without rendering.

3. **Unbroken folder/current-version titles** (potential P3). Folder buttons at `src/vencord/ui/PanelPersonalLibrary.tsx:250` and the current-version title at `:218` render plain `strong` text. `src/vencord/ui/panel-personal.css:27` supplies a flex folder row, with no local min-width or wrapping rule for its title; note titles also lack wrapping. Use a stub folder title of 120 consecutive `W` characters, expand Folders at 360×640, then test a conflict whose current template title is 160 consecutive `W` characters. Check for horizontal overflow and displaced project labels. If reproduced, constrain the title flex item and add `overflow-wrap: anywhere` (or deliberate truncation with access to the full title). No visual verification performed.
