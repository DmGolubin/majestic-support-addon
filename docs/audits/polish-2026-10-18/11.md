## Verified findings

### 11.1 — P2: Field values containing a literal caret marker are silently changed

- Location: `src/core/tokens.ts:51`–`52`.
- Trigger: Create the ordinary field `{{поле}}`, then enter `A{|}B` in its fill dialog. Call equivalent: `fill('Значение: {{поле}}', { поле: 'A{|}B' }, env)`.
- Actual: `{ text: 'Значение: AB', caret: 11 }`. Expected: entered value remains `A{|}B`, with no template caret requested.
- Consequence: field data is interpreted as template syntax after substitution and silently loses characters. The active field workflow reaches this through `flow.ts:115`; it uses the corrupted `.text`. This does not depend on exposing a caret button in the simplified toolbar.
- Minimal fix: recognize caret markers only in source-template segments while expanding tokens, preserving replacement values verbatim and calculating the resulting caret offset from accumulated output length.
- Evidence: isolated in-memory TypeScript transpilation of the actual `tokens.ts`, Node strict assertion against the actual result above passed. Existing token tests cover a marker in template text but not in replacement data.

### 11.2 — P3: Greeting split removes indentation from the first body line

- Location: `src/core/text.ts:25`; the fallback at line 30 has the same trimming behavior.
- Trigger: template text `Здравствуйте!\n[[greeting:end]]\n    first code line\n    second code line` with deliberate four-space indentation on both body lines.
- Actual: `splitGreeting(text).body` is `first code line\n    second code line`. `stripMarker(text)` is `Здравствуйте!\n    first code line\n    second code line`.
- Consequence: the first line's indentation is lost in preview (`Preview.tsx:33`) and insertion without greeting (`flow.ts:203`), while ordinary insertion retains it. This is a verified text/layout mismatch; no claim about Discord's interpretation as a Markdown code block is needed.
- Minimal fix: trim boundary-separator blank lines without consuming horizontal indentation on the first nonblank body line. Apply the same rule to the paragraph fallback.
- Evidence: isolated execution of the actual `text.ts` with Node strict assertions verified both outputs above. Existing boundary tests cover LF/CRLF and inline separation, but no indented body.
