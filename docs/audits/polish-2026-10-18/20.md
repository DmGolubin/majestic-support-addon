## Verified finding

1. **P2 / Medium — Accepted prerelease host directory cannot boot, including vanilla mode.**
   - **Location:** `standalone/runtime/loader.cjs:22-23`; acceptance counterpart: `standalone/installer/SupportTemplates.ps1:300`.
   - **Trigger:** Installation targets an otherwise valid `DiscordCanary/app-1.0.1251-beta.1/resources` directory. The installer accepts the prerelease suffix, while the loader's host expression accepts only three numeric components.
   - **Consequence:** The loader throws `Invalid original Discord location` before configuration fallback or the `--vanilla` branch. Original Discord does not bootstrap, despite its backup being available. This is an independently reproduced **existing Q11**, not a new roadmap item.
   - **Minimal fix:** Align the loader's host-version grammar with the installer's existing supported grammar, retaining channel, containment and redirect checks. Add a mocked loader regression covering a prerelease host with invalid configuration and with `--vanilla`.
   - **Evidence:** Executed the actual loader source using `node:vm`, `path.win32`, fake filesystem/Electron/process objects, and recorded original-module loads. No actual host files were accessed. For `1.0.1251`, installer grammar accepted the name and original Discord loaded. For `1.0.1251-beta.1`, installer grammar accepted the name but the loader threw the error above and original Discord did not load, even with `--vanilla`.
   - **Limit:** No evidence that an installed user host currently uses a prerelease directory; only the supported-path mismatch and its consequence are verified.
