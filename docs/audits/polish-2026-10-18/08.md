## Verified finding

### 08-1 — P2: stale inline popup consumes keys outside its editor

- Exact location: `src/vencord/ui/inline.ts:202` (`handleInlineKey`), especially lines 206–220; lifecycle omission at lines 97–104. Global caller: `src/vencord/index.tsx:120`.
- Trigger: in an enabled server, type a matching trigger to open suggestions, then move focus to a non-Slate control (for example a focusable button) without changing the document selection or typing. Press ArrowDown/ArrowUp. The same problem can occur before the scheduled selection check has run after a focus transition.
- Consequence: the document capture handler prevents the focused control's keyboard action and changes the hidden/stale popup selection. Enter/Tab can similarly be swallowed even though acceptance immediately returns because there is no focused editor. `startInline()` listens only for input and selectionchange; a focus change alone is not required to change the document Selection, so there is no guaranteed cleanup.
- Minimal fix: before handling popup keys, synchronously require a focused Slate editor with a matching current trigger; otherwise close the stale popup and return false. Also schedule popup cleanup on focus changes. Preserve intentional popup mouse-down behavior and the existing in-flight acceptance latch.
- Evidence: an isolated stdin Node VM executed the actual transpiled `inline.ts` with controlled DOM/search dependencies. Opened a popup through its registered input/RAF handler, changed `document.activeElement` to a non-Slate object, then called ArrowDown. Observed `true` (consumed) and `sel: 0 -> 1`; asserted that no focusin/focusout listeners were registered. Caller inspection confirms true causes preventDefault/stopPropagation. This establishes handler behavior; no live Discord/browser reproduction was performed.

## Hypothesis excluded from verified findings

`inline.ts:85` preserves an old selected index when the same query has fewer hits. A controlled 6 -> 2 hit transition retained `sel=5`; Enter was consumed with zero prepareText calls. However, panel catalog replacement calls invalidate() and clears inline state (`panel.ts:280`), so a normal user-facing path producing that transition was not established in this focused pass. Do not treat this as a verified shipped defect without such a path.
