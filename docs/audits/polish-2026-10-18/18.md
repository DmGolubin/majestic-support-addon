## 1. P2 — Store hooks miss changes between render and passive subscription

- **Exact locations:** `src/vencord/ui/uiState.ts:98` (`useTechProject`) and `src/vencord/ui/uiState.ts:105` (`useStore`). Chat button consumer: `src/vencord/index.tsx:52` and `:56`.
- **Trigger:** Mount a consumer while a store load, routed-store replacement, or preference update completes after its initial render but before its passive effect subscribes. Render with `techProject = "mj"`, publish `"ro"`, then run the subscription effect.
- **Observed consequence:** No state update is requested. `useTechProject` continues returning `"mj"` even on a subsequent render, although the store contains `"ro"`; the Tech chat button can therefore show the wrong project until another store notification arrives. `useStore` similarly misses its invalidation, leaving consumers dependent solely on it stale until another render/event.
- **Minimal fix:** Subscribe first, then immediately synchronize `useTechProject` state from `store.data.techProject`. For `useStore`, request one initial invalidation after subscribing, or compare a captured store revision/selection and invalidate when changed. This is the same render-to-subscribe gap already handled in `observable.ts:36–40` and `:54–64`.
- **Evidence:** An isolated Node/TypeScript VM reproducer executed the actual two function declarations extracted from uiState.ts, with render and passive effects controlled separately. Both returned the old value with zero updates after the missed notification. A later notification updated both; cleanup removed both subscriptions. This verifies the hook race; its frequency in live Discord was not measured.

Reproduction (PowerShell; reads only the source and installed TypeScript):

```powershell
@'
const fs = require('node:fs'), vm = require('node:vm');
const ts = require('typescript'), assert = require('node:assert/strict');
const text = fs.readFileSync('src/vencord/ui/uiState.ts', 'utf8');
const sf = ts.createSourceFile('uiState.ts', text, ts.ScriptTarget.Latest, true);
for (const name of ['useTechProject', 'useStore']) {
  const fn = sf.statements.find(n => ts.isFunctionDeclaration(n) && n.name.text === name);
  const code = ts.transpileModule(fn.getText(sf).replace(/^export\s+/, ''), {
    compilerOptions: { target: ts.ScriptTarget.ES2022 }
  }).outputText;
  const subs = new Set(); let effect, state, initialized = false, updates = 0;
  const store = { data: { techProject: 'mj' }, subscribe(fn) {
    subs.add(fn); return () => subs.delete(fn);
  }};
  const scope = { store, useState(initial) {
    if (!initialized) { state = initial; initialized = true; }
    return [state, next => { updates++; state = typeof next === 'function' ? next(state) : next; }];
  }, useEffect(fn) { effect = fn; }};
  vm.createContext(scope); vm.runInContext(code, scope);
  const before = scope[name]();
  store.data.techProject = 'ro'; subs.forEach(fn => fn());
  const off = effect(); const after = scope[name]();
  assert.equal(updates, 0); assert.equal(after, before);
  console.log(name, { store: store.data.techProject, returned: after, updates });
  subs.forEach(fn => fn()); assert.equal(updates, 1);
  off(); assert.equal(subs.size, 0);
}
'@ | node
```

Actual output: `useTechProject` returned `mj` with store `ro`, updates `0`; `useStore` returned version `0`, updates `0`.
