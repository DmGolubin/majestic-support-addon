## Verified finding

### 09-1 — P2: ordinary template insertion survives changes to the destination draft during an async wait

- **Location:** `src/vencord/ui/flow.ts:22` (snapshot fields), `:29` (validation), and `:215` (focus and unconditional insertion after validation).
- **Trigger:** Start an ordinary template insertion containing `{{clipboard}}`. While clipboard access is pending, edit the existing draft in the same connected editor. Complete the pending clipboard read. The same issue can occur during a pending freshness check; that variant was not separately executed.
- **Observed consequence:** The original operation still focuses the captured editor and invokes `insertText` with the prepared answer against the changed draft. The operation does not reject a draft that the user edited while waiting. Actual text replacement versus appending depends on the host editor's current selection; destructive replacement was not tested or claimed. No automatic message sending was observed in this path.
- **Cause:** `Snap` captures channel, scope, generation, library version, editor identity, and selection text, but no draft revision/content or caret context. `stillCurrent` checks connectivity and channel/library/lifecycle identity only. The ordinary insertion path therefore lacks the draft-change cancellation already present in the inline path.
- **Minimal fix:** Capture a lightweight draft revision or text fingerprint for the target editor at operation start and reject changes before insertion. Preserve the intended caret/selection context as needed, while permitting ordinary focus handoffs through plugin dialogs. Add a focused regression exercising actual `flow.ts`, with a deferred clipboard/freshness dependency and a draft change before resolution.
- **Test evidence:** An isolated Node stdin reproducer transpiled and executed actual `flow.ts` using TypeScript and `node:vm`; only dependencies were mocked. It called `insertTemplate` with an actual-status FAQ containing `{{clipboard}}`, held `readClipboard` on a deferred promise, changed `editor.textContent` from `Original draft` to `New draft typed while waiting`, then resolved the promise with `Template answer`. Channel, scope, generation, library version and template identity remained stable. The insertion spy recorded one call against the changed draft. Separate control runs changed channel or generation during the same wait and recorded zero calls. Assertions passed; no reproducer file was created.
