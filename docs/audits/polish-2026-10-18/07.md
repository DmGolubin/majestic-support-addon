## Verified findings

### 07-1 — P2: Enter activates insertion instead of the focused preview action

- Location: `src/vencord/ui/Window.tsx:370` and `:397-402`. Supporting controls: `src/vencord/ui/Preview.tsx:35` and `:58-61`.
- Trigger: Open/pin the preview, Tab to “Без приветствия”, “+ в ответ”, the favorite button, or compact “назад”, then press Enter. These native buttons have neither `.vc-stx-select` nor `[data-stx-menu-control]`, so their keydown bubbles into the Window handler.
- Consequence: Window prevents the native button activation and calls `insertTemplate(current, { via: "window-enter" })`. Adding to the composed reply, omitting the greeting, toggling favorite, or returning to the list instead inserts the full template.
- Minimal fix: Exempt preview action buttons from list activation/navigation (reuse the existing control marker, or narrow the Window target guard to include these buttons). Preserve list shortcuts while search owns focus.
- Evidence: Ran the actual Window `onKeyDown` body, extracted and TypeScript-transpiled in an isolated Node VM, with an Enter event whose target matches the unmarked Preview button. Assertions passed: default prevented; exactly one insertion; `via === "window-enter"`. Source inspection confirms all listed buttons are focusable native buttons with no exemption marker. No live browser reproduction was attempted.
- Regression to add in parent pass: keyboard-focus each preview action and dispatch Enter; assert its own action occurs once and generic window insertion does not occur.

### 07-2 — P2: Context menu executes IME Enter with keyCode 229

- Location: `src/vencord/ui/ContextMenu.tsx:113-128`, specifically the incomplete composition guard at `:117`.
- Trigger: With a visible context menu, deliver a composition-related Enter where `keyCode === 229`, `isComposing === false`, and `repeat === false`. This is the IME fallback event shape already guarded by Window at line 363 and Select at line 51.
- Consequence: The active menu item executes; on a newly opened menu this is “Вставить”. Confirming composition can therefore insert a template. The menu also prevents default before checking composition, unlike the other controls.
- Minimal fix: Check `e.isComposing || e.keyCode === 229` before preventing default or dispatching menu commands, consistent with Window/Select.
- Evidence: Ran the actual ContextMenu `key` handler, extracted and TypeScript-transpiled in an isolated Node VM. Sent `{ key: "Enter", code: "Enter", keyCode: 229, isComposing: false, repeat: false }`; assertion passed that `run(0)` executed once. `index.tsx:112` yields to an open context menu, so the global shortcut handler does not supply the missing guard.
- Validation limit: Handler behavior is reproduced synthetically; occurrence with a particular OS/IME was not tested. This report does not claim live IME acceptance testing.
- Regression to add in parent pass: composition events using both `isComposing` and keyCode 229 must not run a menu item or consume composition input.
