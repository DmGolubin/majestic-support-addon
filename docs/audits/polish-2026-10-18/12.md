## 1. P2 — Popup placement ignores the editor's actual clipping boundary

- **Location:** `src/vencord/ui/Select.tsx:35` (bounds lookup; direction and height calculation at lines 37–41). Relevant CSS: `src/vencord/ui/settings-layout.css:44`; `src/vencord/styles.css:373` and `:377`. The editor contains the folder Select at `src/vencord/ui/PanelPersonalLibrary.tsx:207`, inside the body introduced at line 191.
- **Trigger:** At a window height above 540px, open the personal template editor with enough folders to require a tall list, scroll the folder combobox into view, and open it near the editor body's edge. The parent supplied a 900×550 / 12-folder browser observation: popup top 213.8px while editor-body clipping starts at 219.3px. This reviewer did not repeat that browser run.
- **Cause / consequence:** `closest(".vc-stx-settings, .vc-stx-win")` skips `.vc-stx-pp-editor-body`, whose `overflow:auto` clips the absolutely positioned list. Direction and `maxHeight` therefore include space outside the actual visible scroll body; the popup and its options can be partially hidden. Increasing z-index cannot escape the ancestor's overflow clip.
- **Minimal fix:** Compute usable top/bottom from the viewport intersected with the actual overflow-clipping ancestors, including the editor body's inner scrollport. Use those bounds for both opening direction and popup height. Account for the existing popup gap and box sizing. At the <=540px CSS fallback the body has `overflow:visible`, so it must not be treated as the clipping container; settings becomes the relevant scroller.
- **Test evidence:** An isolated Node stdin reproducer extracted and executed the actual `show()` function from `Select.tsx` with 12 options, viewport height 550, button rect top/bottom 320/350, settings bounds 100/500 and editor clip 219.3/430. Actual output: upward=true, maxHeight=200. With the production 4px gap, a 200px border-box popup starts at 116, outside the body by 103.3px. Intersecting with the editor bounds gives maxHeight=92.7 and top=223.3. This verifies the bounds-calculation defect with synthetic geometry; it is not a DOM rendering measurement. Existing `tests/menuRefinement.test.ts` mocks only one container and therefore does not catch the nested clip.
- **Suggested regression:** Exercise actual nested editor scrolling at 900×550 with 12 folders, checking the list rectangle against the editor scrollport after opening and keyboard End/Home. Also cover <=540px, where settings owns scrolling.
