## Verified finding and minimal fix

**Q11 — P2 / Medium, fixed in source.** The installer accepts `app-1.0.1251-beta.1` (`standalone/installer/SupportTemplates.ps1:300`, also uninstall enumeration at line 325). The baseline loader's line 22 permits only three numeric components. Line 23 then throws `Invalid original Discord location` before either configuration recovery or the vanilla branch. A valid backup therefore cannot bootstrap for an installer-supported prerelease directory, including with `--vanilla`.

Priority rationale: this prevents startup and the vanilla escape path for that directory class, but no evidence establishes that the user's actual installed host has such a suffix. This is the existing Q11, not an additional incident or a claimed explanation for the owner's earlier startup/UI problem.

The fix adds the installer's exact optional suffix fragment, `(?:-[0-9A-Za-z]+(?:[.-][0-9A-Za-z]+)*)?`, to the loader host expression (`standalone/runtime/loader.cjs:23`) and adds an alignment comment. Numeric core, supported channel names, anchored directory layout and redirect checks remain in place. This intentionally matches the existing installer grammar, not every possible SemVer string: build metadata, underscores, empty suffix components and doubled separators remain rejected.
