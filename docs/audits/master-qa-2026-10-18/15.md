## Confirmed findings (pre-fix evidence; now addressed above)

### 15-1 — P2: Alt-number consumes unrelated input when no template occupies that slot

- Evidence: `src/vencord/index.tsx:144–160`. On an enabled guild, with no dialog/menu/management surface and focus outside a native foreign input, Alt+1…9 calls preventDefault/stopPropagation **before** looking up the candidate. If favorites/visible items do not have that index, no plugin action occurs, but the event is still consumed.
- Reproduction: empty favorites, template window closed, dispatch Alt+9 from body/chat. The actual extracted handler in an isolated TypeScript VM prevented and stopped the event once, with zero insertion calls.
- Impact/priority: another plugin's shortcut or default behavior is suppressed for an unavailable action; bounded keyboard interoperability defect, P2. No live cross-mod impact was measured.
- Minimal fix: resolve the candidate first and return without consuming when absent. Retain repeat suppression for an action actually started/latched. Add empty and populated slot regressions.

### 15-2 — P2: foreign contenteditable fields are not protected from personal binds

- Evidence: `src/vencord/index.tsx:75–78,144–148,170–180`. `inForeignInput` only recognizes `input, textarea, select`; another plugin's rich editor can be contenteditable without any of those ancestors. Matching personal binds then consume the event and invoke insertion flow. Alt-number has the same guard gap.
- Reproduction/code proof: actual handler in an isolated VM, enabled guild, bound Ctrl+K, event target with `isContentEditable: true` and no native-input/plugin-root ancestor. Observed preventDefault and an insertion-flow call. Native foreign input control passed through.
- Impact/priority: unrelated rich-editor input can become a template action, P2. Actual text insertion was NOT exercised: platform/editor checks can still cancel it. `src/vencord/ui/op.ts:38–40` obtains the current editor and `src/vencord/platform.ts` activeEditor can fall back to a main Slate editor, so final focus/text behavior requires a host fixture or live acceptance; do not treat unintended insertion as demonstrated.
- Minimal fix: classify editable ancestors including contenteditable/role=textbox, allow plugin-owned controls and the verified chat editor explicitly, and ignore foreign editable targets before resolving personal binds/favorite actions. Test a nested child of a foreign rich editor and an allowed chat editor.

### 15-3 — P2: global window shortcut disregards an earlier claim and extra Meta modifier

- Evidence: `src/vencord/index.tsx:110–140,250`. The document capture handler has no `defaultPrevented` guard; Ctrl+Alt+T requires no Shift but does not require no Meta. It therefore also owns Ctrl+Alt+Meta+T. By comparison, Alt-number explicitly excludes Meta at line 145 and the window's local handler respects `defaultPrevented` (`src/vencord/ui/Window.tsx:364`).
- Reproduction: actual handler in the same isolated VM: Ctrl+Alt+T with `defaultPrevented: true` toggled the window; Ctrl+Alt+Meta+T also toggled it. Neither is inferred from a hypothetical mod implementation.
- Impact/priority: an earlier capture listener cannot cancel the plugin action using normal default prevention, and a distinct chord is claimed. P2 for cooperative keyboard behavior; no claim that stopPropagation blocks other listeners registered on the same document (it does not).
- Minimal fix: after deliberate latched-key handling, respect defaultPrevented before new actions; require `!e.metaKey` for the fixed shortcut. Add both event cases. Shortcut precedence for ordinary same-chord third-party listeners remains integration-specific.
