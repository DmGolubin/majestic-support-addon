## Findings

### R18-01 — P2: pinned source does not enforce pinned build dependencies

**Code proof:** `standalone/config.json:4` pins upstream commit `32c90633ce6a95d7e56c95479efbb431bacf1eac`. `standalone/build.mjs:25` archives that commit, but line 51 junctions the caller-selected Vencord checkout's existing `node_modules` into the archived source. Line 53 then executes compilation using that tree. `standalone/compile.mjs:6` imports esbuild from it; lines 62–75 record four resolved package versions after compilation without comparing package contents or the complete resolved tree to the archived lock. `standalone/build.mjs:77` ships the archived lock as source evidence regardless of which dependency bytes were consumed.

**Reproduction by code inspection:** retain the configured commit while supplying a base checkout whose installed dependency tree differs from that commit's lock. The recipe still uses the changed tree. No frozen installation, integrity verification or preflight lock/tree comparison occurs in the inspected recipe. This is a supported code path, not an experiment performed on the user's dependency tree.

**Priority rationale:** build-host drift can change generated runtime code while retaining the same upstream revision and archived lock. This weakens reproducibility and supply-chain attestation. P2 because no actual mismatch, malicious package or compromised build is established. The inspected local versions and `.12` toolchain record agree for esbuild 0.28.1, TypeScript 6.0.3, xxhash64 0.1.2 and diff 9.0.0. This gap was already noted in the earlier standalone dependency report; it is not newly discovered compromise.

**Minimal fix recommendation:** in separately authorized build work, prepare dependencies from the archived lock in a disposable environment with a frozen install, or fail before compilation unless the reused tree has verifiable provenance matching that exact lock. Keep toolchain/metafile evidence, but do not treat four version strings as complete integrity verification. No fix applied under this read-only assignment.
