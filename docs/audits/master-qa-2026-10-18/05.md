## Findings

### M05-01 — P1: failed button-to-editor lookup silently changes the insertion target

**Evidence:** `src/vencord/index.tsx:58` passes `editorNear(e.currentTarget)` into `toggleWindow`; `index.tsx:39-42` captures that result. `ui/op.ts:32-33` depends on an ancestor class containing `channelTextArea`. If that lookup fails, `op.ts:27-28` treats the explicit null as permission to call `activeEditor()`. `platform.ts:60-62` then picks a global Slate editor if focus is on the button. `flow.ts:27-28,40-51,240-248` validates the editor already chosen, focuses it and dispatches insertion; it has no record of the failed sidebar lookup.

**Concrete synthetic reproduction:** `tests/masterCompatibility.test.ts:94` executes real platform, op and flow modules. A sidebar-button fixture returns null for its ancestor lookup; focus is outside Slate; global query returns a connected main editor. Capturing the button target selects the main editor. The real flow focuses that main editor, invokes the mocked insertion helper once with the reply, and marks the template used. This proves target substitution and dispatch, not actual Slate insertion into a live channel.

**Priority rationale:** P1 because compatibility drift can direct a prepared support reply toward another conversation's draft without a cancellation. It does not send messages. Trigger conditions are conditional: the ancestor selector must fail while another matching editor exists. No evidence that the current Canary DOM has drifted.

**Minimal fix / safe degradation:** distinguish “no explicit target requested” (keyboard-open path) from “explicit chat-button target could not be resolved.” On the latter, cancel insertion and show a non-throwing notice; do not fall back to a global editor. Require a connected target before preparation and final dispatch, including the null-target path. Keep the library available for manual copying and allow retry after the user focuses the intended editor. Parent should own the small index call-site adjustment. Regression acceptance: the reproduction must dispatch zero times and mark no usage; normal main/sidebar captures must still work.

### M05-02 — P2: missing required host modules escape the adapter instead of disabling the affected capability

**Evidence:** `platform.ts:38-45` directly dereferences `SelectedGuildStore`, `GuildStore`, `SelectedChannelStore`, `ChannelStore`; `platform.ts:49-56` directly invokes dispatcher and toast methods. Local Vencord exports these stores via `waitForStore` assignments (`../Vencord/src/webpack/common/stores.ts:50-52,120-122`), and locates `showToast` by a code signature (`common/utils.ts:69`). Type declarations do not establish runtime availability after lookup/signature failure.

**Concrete synthetic reproduction:** parameterized tests at `tests/masterCompatibility.test.ts:48` remove each of five dependencies and demonstrate escaped exceptions. The test at line 56 removes `getGuildId` and `showToast`, also demonstrating escaped exceptions. These execute the actual adapter; missing dependencies are deliberately injected. No missing module was observed in live Discord.

**Integration consequence, code proof:** `ui/uiState.ts:64-75` uses the unguarded guild lookup for feature gating; `index.tsx:115` calls that gate from keyboard handling. The optional sound startup directly subscribes at `ui/ticketSound.ts:319`, and is called before host mount at `index.tsx:245-252`. Its unsubscribe at `ticketSound.ts:303` can also interrupt cleanup if the dispatcher disappears. These are propagation paths; this review did not execute complete plugin startup with a missing dispatcher. Parent owns startup/cleanup implementation and Q09, which remains a separate storage failure.

**Priority rationale:** P2 availability/resilience issue conditional on host discovery or method failure; an optional integration can prevent later initialization or cleanup. No current startup outage is attributed to it.

**Minimal fix / safe degradation:** put capability checks and exception containment at the adapter boundary, including lazy proxy property access. Unknown channel/guild must disable insertion and hotkey interception; it must not reuse a stale guild or grant a default scope. Surface one compatibility notice through a fallback that does not require `showToast`. Subscription setup should either return a safe disposer or report unavailability; sound failure should leave the library usable. Cleanup must continue if unsubscribe fails. Ensure availability can be retried after the host resolves modules rather than permanently caching the first miss. Apply equivalent treatment to the direct ticket-sound consumer; parent coordinates any index changes.

### M05-03 — P3: insertion fallback does not contain synchronous clipboard bridge failures

**Evidence:** `platform.ts:23-33` catches insertion failure, but evaluates `navigator.clipboard?.writeText(text)` synchronously inside that catch without a second guard. A synchronous throw bypasses both toast handlers and the promised `false` return. `inline.ts:237` and `index.tsx:150,171` launch asynchronous insertion flows without awaiting them; such an escape can become an unhandled rejection.

**Concrete synthetic reproduction:** `tests/masterCompatibility.test.ts:87` makes insertion throw, then makes the clipboard bridge throw synchronously. Actual `platform.insertText` throws the bridge error and emits no notice. This is fault injection for a replaced/broken bridge, not a claim that standards-compliant browser clipboard denial throws synchronously (normally it rejects a promise).

**Priority rationale:** P3 because it requires two failures, and normal promise rejection is already handled. The failed operation loses its intended user-facing recovery message.

**Minimal fix / safe degradation:** invoke the clipboard capability inside a deferred promise/guard, normalize its return, and contain failure reporting as well. Return false reliably; announce copy only after fulfillment, and present manual copying on failure. Never retry insertion automatically because the first dispatch may have partially executed.
