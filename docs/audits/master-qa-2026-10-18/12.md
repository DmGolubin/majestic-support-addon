## Confirmed findings and fixes

### R12-01 / C08 — P2: malformed catalog content destroys a valid local session

**Evidence / reproduction:** with a valid authenticated `/me`, matching snapshot account/projects/permissions metadata and `faq: null`, the original parser throws a plain `Error`. The original controller only retries qualifying `PanelError` transport failures, so it invokes `terminateSession`; `PanelClient.cancel()` clears saved credentials (`src/core/panelClient.ts:301`, `305`). This was reproduced for first connect, restored login and an already loaded catalog, using the real catalog parser and real controller in a VM. All three red tests received `phase: "error"` instead of `"offline"` before production edits. Repro command:

```text
node node_modules/vitest/vitest.mjs run tests/panelIntegration.test.ts -t "recovers malformed authenticated snapshot"
```

**Priority rationale:** a bad library response forces avoidable reauthorization and interrupts access. This is a functional recovery defect, not evidence of unauthorized disclosure or a confirmed live server incident. No production malformed response was fetched in this work.

**Minimal production fix:** `PanelCatalogValidationError` carries `kind: "access" | "data"` (`src/core/panelCatalog.ts:74`). Snapshot identity, schema, projects, required scopes and permissions revision validate before entering the content parser (`221` onward); only known content validation failures are reclassified as `data` (`233`, `235`, `240`). Unknown exceptions retain their prior terminal behavior. Profile/envelope validation remains terminal.

The controller retries typed `data` errors using its existing backoff (`src/vencord/ui/panel.ts:317`, `322`) while keeping `panelAccess.ready` false, invalidating pending insertion UI and stopping reminders (`314` onward). It retains the authenticated client/vault and publishes only a later fully validated catalog. Existing freshness/access gates remain in place (`src/vencord/ui/uiState.ts:34`, `70`). The error message identifies library-content validation and explains the retry/insertion block; no raw payload, token, account identifier or converter exception is included (`src/vencord/ui/panel.ts:86`).

**Fail-closed evidence:** unit cases reject foreign/missing identity, unsupported schema and inconsistent permissions/projects before content classification (`tests/panelCatalog.test.ts:57`). Controller tests still reject foreign profile/connection, missing scopes and incompatible version (`tests/panelIntegration.test.ts:386`), preserve revocation priority over parallel transport failure (`365`), and cancel on delayed invalidated auth errors (`465` onward). Added real-client/vault-adapter tests prove a foreign snapshot, final 401, 403 and `session_revoked` during recovery clear saved credentials and stop polling (`tests/panelSessionIntegration.test.ts:130`). Existing SSE revocation tests also pass (`tests/panelIntegration.test.ts:804`). The real client retains its normal one-refresh handling of 401 before the controller receives a final failure.

### R12-02 — P2: fractional backoff can consume the only retry without loading

**Evidence / reproduction:** after R12-01's classification fix, all three recovery tests still failed: credentials survived, but the expected second `/me` + `/snapshot` never ran. With `Math.random = 0.50001`, first backoff is `10000.04 ms`. Timers truncate the fraction, so the callback can run at `10000 ms`, before the fractional `retryAt`. `loadLibrary()` returns early, and that callback schedules no replacement. The same tests were rerun with this deterministic jitter and again failed at the expected request count (2 vs 4, or 4 vs 6).

**Priority rationale:** this can strand automatic catalog recovery after a transient failure until a later external/manual trigger. It directly blocks the requested C08 recovery path. Browser timing incidence was not measured; fake-timer reproduction and the timestamp comparison establish the code defect.

**Minimal fix:** round the computed delay up once and use that integer for both `retryAt` and the timeout (`src/vencord/ui/panel.ts:195–201`). This does not shorten Retry-After. The tests verify early repeated reload/freshness calls make no additional requests, then the scheduled retry succeeds without another login (`tests/panelIntegration.test.ts:497`).

- This fixes malformed **content after a validated access envelope**. Missing/foreign identity, missing/inconsistent rights metadata, unsupported snapshot schema, malformed `/me`, unexpected programming exceptions and raw transport/protocol `invalid_response` errors remain terminal.
