# Живая проверка входа — 18 октября 2026

Проверка начата в установленном Discord по просьбе владельца. Подтверждение доступа на панели выполняет владелец. Сообщения в Discord не отправлялись; токены и cookies не извлекались.

## Подтверждённые препятствия на стороне плагина

1. `panelEndpoint()` отклонял подчёркивание в документированном `/oauth/device_authorization`. Запрос не отправлялся. Добавлен регрессионный тест реального PanelClient вместе с реальным построителем URL и HTTP-транспортом (только fetch подменён). До исправления он падал с `invalid_request`, после проходит.
2. После исправления маршрута живой Discord отклонил fetch по CSP: `connect-src` не включал `panel.majestic-rp.tech`. Это подтверждено сообщением DevTools, а не выводом из HTTP-статуса API. До сервера эта попытка не дошла.

Исправление использует штатный `VencordNative.csp.requestAddOverride`: только фиксированный домен панели и `connect-src`. Автоматическое восстановление сессии не открывает запрос разрешения. Отказ, отсутствие галочки и ошибка IPC не запускают авторизацию. После разрешения интерфейс требует полного перезапуска Discord. Изменения политики без согласия пользователя и отключение CSP не применялись.

В 15:53 по Бухаресту в живом Discord открылось окно `Vencord Host Permissions` для домена панели. Дальнейший шаг передан владельцу: отметить доверие, нажать Allow и полностью перезапустить Discord. Нажатие разрешения агентом не выполнялось.
