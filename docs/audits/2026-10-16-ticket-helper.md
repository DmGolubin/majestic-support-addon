# Помощник тикетов — первый блок, 16.10.2026

## Реализовано

Звук нового тикета на основе reference/ticket-sound: THREAD_CREATE, два исходных родительских ID, только MJ/RO. Обычные сообщения больше не вызывают звук. Отдельное локальное хранение настроек, выключатель (по умолчанию off), громкость, тест, пауза 1/3/5/10 с, настройка каналов, подавление открытого тикета в фокусе. SVG для раздела «Тикеты».

Фильтр свежего ID (после запуска, не старше 30 с), отклонение явного newlyCreated=false/архива, дедупликация до 1000 ID, отсутствие очереди подавленных звуков. После stop отписка и закрытие AudioContext; после запоздавшего load компонент не включается обратно. Записи тикетов, текст обращений и сообщения бота не читаются/не отправляются. Звук Web Audio может быть заблокирован окружением: сообщается в настройках, предлагается тест по клику, старые сигналы не копятся.

Личные напоминания: только чистое ядро reminderDue/reminderKey и тесты порогов 5/10/15, чужого ответственного, ответа, возврата, закрытия, идентичности периода. Транспорт, UI настройки интервала, сохранение отметок и реальный автоматический таймер ещё не реализованы. Нельзя объявлять B03 готовым.

## Проверки

139 тестов, typecheck ядра, ESLint и сборка Vencord. Браузерный стенд настоящих TicketSettings/ticketSound с подменой границ Discord/storage/audio: создание аудиографа, дедупликация события, сохранение после reload, невалидные ID, dropdown, выключение, cleanup, 390 px без переполнения и без ошибок JavaScript. Снимок docs/screens/ticket-settings.png.

Аудиограф с mock AudioContext не является проверкой слышимости. Живая приёмка реального THREAD_CREATE и звук на устройстве ещё нужны. Настройки доступны после Ctrl+R. Discord в этом блоке не перезагружался, сообщения не отправлялись, старый TicketSound автоматически не отключался. Повторная проверка старых сценариев FAQ не проводилась; они не изменялись.

## Источники и ограничения

Профиль панели прочитан через авторизованный браузер: подтверждены Telegram-подключение и перенос настроек в Mini App. Схема API и данные назначения не получены. Скриншот пользователя и его правила — источник требований 20/30 минут, а не доказательство API. Документация Discord подтверждает двойную семантику THREAD_CREATE; внутренний Flux может отличаться и требует живой проверки.

Фильтр времени намеренно пропускает события с задержкой более 30 секунд. При добавлении в очень свежую приватную ветку без флага новизны возможна неоднозначность. Системные часы влияют на отбор свежих snowflake. Доставка быстрее стандартных уведомлений не гарантируется. Таймер нельзя достоверно привязать к ответственному только по упоминанию бота, автору или участнику ветки.

## Передано в ТЗ

TICKET-HELPER-SPEC.md и TICKET-DEVELOPER-MESSAGE.txt: независимые личные 5/10/15, системные 20 и серверные 30; предлагаемый read-only снимок своих тикетов, изменения состояния, семантика ожидания, настройки Telegram, отдельные права и приёмка. Наличие API не заявляется. При отсутствии данных автоматический таймер не включаем; ручной режим требует отдельного решения.
