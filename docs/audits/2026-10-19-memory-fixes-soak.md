# Исправление утечек и длительная проверка .20

Проверяемая локальная BetterDiscord-сборка: `1.0.1-canary.20`, исходники `a5aa98d4ec95e58b1c0a8770455fc0fd04001bdd`, SHA-256 `3838ad2a7f22b5488cb3bf2e1d18fea9e279af04da00eff3db766701ee3071c0`.

## Изменения

- Частичный запуск кнопок BetterDiscord откатывает observer, подписку, RAF и DOM, включая ошибку создания React root и ошибку последующего перемонтирования composer.
- Остановка обрабатывает ресурсы независимо. Ошибка одного cleanup не пропускает остальные; ссылки владельца отсоединяются перед вызовом внешнего кода. Общий runtime также откатывает неудачный startup.
- Для подписок панели, toolbar и общей смены канала предусмотрена ограниченная повторная попытка снятия. При постоянном отказе callback становится неактивным, сохраняется только для повторной очистки; новые поколения подписок не накапливаются. После восстановления хоста старый callback удаляется. Нельзя гарантировать физическое удаление подписки, если сам хост постоянно отказывает в unsubscribe.
- Ссылки закрытого списка и пустого compose освобождаются. Уже захваченный контекст ожидающей вставки не изменяется. Список горячих клавиш публикуется после React commit и очищается при unmount.
- Изменения сообщений, ввод внутри Slate и отрисовка собственной кнопки не вызывают полный поиск composer. Добавление/удаление composer, toolbar и редактора по-прежнему обнаруживается.

Расширенная проверка постоянного отказа `CHANNEL_SELECT` сначала обнаружила вторую подписку в общей `platform.ts`. Этот дополнительный дефект исправлен в `d9e16f3`; неуспешный исходный прогон сохранён отдельно, условия теста не ослаблялись.

Заключительный просмотр также выявил риск повторного входа в toolbar unsubscribe: запись снималась после вызова внешнего кода. В `a5aa98d` запись отсоединяется перед вызовом; добавлен тест повторного входа. Предварительный прогон прежнего hash остановлен на 525,5 секунды без нарушений, помечен `interrupted` и не засчитывается как часовой. Окончательный отсчёт начинается заново для файла выше.

## Проверки исходников и готового файла

- Полный Vitest окончательного исходника: **1 714 / 1 714**, 80 файлов, `--maxWorkers=1`. TypeScript и проверка совместимости исходников с Vencord проходят.
- Первый запуск полного набора выявил два устаревших mock UI без `subscribe`; они заменены на реальный observable с дополнительными проверками вставки. Windows DPAPI-проверка дважды не прошла при параллельной нагрузке. Отдельный повтор, промежуточный полный набор с четырьмя workers и окончательный последовательный набор проходят. Не следует скрывать нестабильность проверки под нагрузкой; production DPAPI не изменялся.
- Готовый bundle: аварийные startup/stop, постоянный отказ unsubscribe и восстановление, отсоединённые цели вставки, освобождение результатов поиска, 120 посторонних изменений DOM, 30 start/stop и 100 BD settings mounts — проходят.
- Независимый просмотр изменений и JSDOM-проверка замены composer/toolbar/редактора не нашли регрессий.

## Методика длительного прогона

Изолированный Chromium с точным файлом выше, React production и настоящим кодом UI, lifecycle, panel client и SSE parser. Подменены Discord stores/event bus, OAuth/API и недоступные native-функции. Это не автоматизация пользовательского Discord. Установленная версия пользователя не менялась.

Выполнено **3 600,20 реальных секунд**, 1 000 циклов открытия списка, настроек и личного редактора, перемежаемых простоем в трёх состояниях. Дополнительно 20 прогревочных циклов. Две потери сети по 20 секунд; OAuth-токен действует настоящие 900 секунд, следующая пара уникальна, повторное использование refresh-token отвергается. Fake clocks не используются.

Перед стартом зафиксированы ограничения относительно прогретого закрытого состояния: heap не более +2 МиБ, DOM не более +10 узлов, JS listeners не более +5, занятость основного потока в измеренных интервалах простоя не более 1%. Эти границы являются условиями данного теста, не гарантией отсутствия медленных утечек.

После двух GC фиксируются JS heap, DOM/listeners, host subscriptions, таймеры, RAF, observers и сетевые счётчики. Инструментация использует WeakRef и раздельно учитывает плагин, fixture и Playwright. Метаданные не удерживают DOM/callback. Занятость основного потока включает React/стенд/инструментацию; это не общий CPU Discord. Проверка после stop требует отсутствия ресурсов плагина и новых API-запросов.

**PASS**, процесс завершился с кодом 0. Все **1 109** проверок часового прогона прошли; необработанных ошибок нет. Полная длительность, включая прогрев и финальную очистку, — 3 612,38 секунды. Все шесть дополнительных проверок готового файла также имеют статус `pass`.

Начальный рост heap не скрыт: память не осталась точно на исходном уровне. Во второй половине теста закрытое состояние стабилизировалось в указанном узком диапазоне. Итоговый heap с **открытым** списком — 6,123 МиБ; после stop — 4,391 МиБ. Сравнивать открытый список с закрытым baseline как доказательство утечки нельзя.

Во время двух введённых сетевых отказов зарегистрированы девять неудачных сетевых попыток; это ожидаемая часть сценария. После восстановления библиотека возвращалась в `ready`. Счётчики API не менялись в дополнительном двухсекундном интервале после stop. Единственный оставшийся MutationObserver принадлежит Playwright.

**Остаточное удержание DOM не объявляется устранённым полностью.** После часового stop CDP показывает 533 DOM nodes / 233 listeners при 13 живых HTML-элементах. Такие же числа наблюдались в исходной .19; владельцы всех отсоединённых объектов не установлены heap snapshot-ом. В отдельном аварийном стенде после stop — 19 / 2, поэтому этот результат нельзя переносить на основной авторизованный сценарий. Подтверждённые глобальные ссылки, активные подписки и таймеры исправлены; полное отсутствие иных удержаний не доказано.

На отдельной проверке 120 посторонних DOM-изменений вызывают **0** дополнительных plugin RAF вместо 121 в исходной .19. Десять аварийных запусков больше не оставляют десять observers и десять Flux-подписок. Проверены также 30 start/stop и 100 монтирований настроек BetterDiscord.

## Границы вывода

Даже успешный часовой прогон не заменяет многочасовую проверку в настоящем BetterDiscord с другими расширениями, реальным Discord React, сетевым API, native updater и сохранением защищённого входа. Общие исходники Vencord проверены типами/тестами; часовой стенд использует BetterDiscord bundle. Автоматическая установка и публикация этого кандидата не выполнялись.
