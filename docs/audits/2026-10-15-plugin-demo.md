# Деморежим внутри плагина — 15.10.2026

## Запуск

1. На ПК: `python scripts/demo-panel.py` из репозитория. Сервер слушает только `127.0.0.1:47833`. Не публиковать его в интернете. Python использует стандартную библиотеку.
2. После сборки плагина перезагрузить Discord. Открыть «Мои шаблоны и настройки» → «Подключение» → «Включить деморежим» → «Начать вход».
3. Нажать «Открыть локальную панель», сверить код и выбрать «Разрешить». Реальный сайт и реальные cookies не используются.
4. Закрыть настройки. В обычном окне шаблонов на MJ/RO/Tech появится тестовый FAQ. Можно искать, просматривать, заполнять поле и вставлять в черновик. Плагин не отправляет сообщение.
5. На локальной странице изменить FAQ и сохранить. В течение очередного двухсекундного опроса плагин заменит каталог и отменит прежние ожидающие вставки/compose. Текст, ранее вставленный в Discord, не меняется.
6. Проверить отказ, повторный вход, паузу связи, восстановление и отзыв устройства. «Выйти из деморежима» возвращает обычную библиотеку.

## Изоляция и ограничения

- Реальное хранилище не заменяется импортом и не перезаписывается: используется отдельный Store в памяти со стабильной фасадной подпиской. Избранное, настройки и личные шаблоны, изменённые в демо, не попадают в обычную библиотеку.
- Демо выключено по умолчанию, не сохраняется при перезагрузке; полоса «ДЕМО» видна в Discord всё время работы режима. Тестовые правки исчезают при выходе.
- Личные шаблоны/папки можно редактировать в демонстрационной библиотеке, но их синхронизация с демосервером пока не реализована — UI говорит об этом прямо. Офлайн-правки редактора не следует считать сохранением на сайте.
- Транспорт — локальный HTTP polling каждые 2 секунды; это не production OAuth/SSE. Сервер держит одноразовые попытки в памяти, выдаёт разные случайные возможности клиенту и странице подтверждения. Возможность клиента не позволяет подтверждать вход и менять FAQ. Pending истекает через 10 минут.
- Нет реальных access/refresh-токенов, защищённого хранилища токенов, политики 30-секундной свежести, сетевой персональной библиотеки и очереди конфликтов API. Эти пункты остаются в ТЗ реальной интеграции.
- При потере связи блокируется область тестовой вставки. При обновлении, отключении режима или остановке плагина меняется поколение операции, старые ответы/таймеры не могут примениться в новой сессии.
- Ручное закрытие локальной страницы не отзывает подтверждённую сессию; для этого есть «Отозвать устройство». Перезапуск демосервера сбрасывает все сессии.

## Проверки

123 модульных теста: в том числе изоляция записей обычного Store, переключение подписок, сохранение личных тестовых записей и избранного при обновлении каталога.

Локальный API: без capability нельзя читать снимок; capability клиента не разрешает согласие и публикацию FAQ; до подтверждения каталог пустой. Production-сайт не затронут.

Дополнительно пройден браузерный стенд реальных компонентов настроек с настоящим loopback API: отказ, повторный вход, согласие, загрузка снимка, обновление FAQ, пауза/восстановление связи, отзыв и выход из режима. Ошибок JavaScript нет. Полный typecheck Vencord, ESLint изменённых файлов и сборка прошли. Это проверка компонентов и транспорта; живой Discord в этом проходе не перезагружался и новый сценарий там ещё не принят.

## Уточнение первого экрана

Меню теперь сразу показывает «Войти через панель», без перехода в настройки и ручного включения демо. Кнопка включает изолированный режим, создаёт попытку и открывает локальное подтверждение. Если браузер не открылся, остаётся повторная ссылка. При разрешении открытое меню автоматически становится библиотекой; цель редактора Discord сохраняется. Возврат к обычным данным доступен отдельной кнопкой. Проверен браузерный путь одним кликом: экран входа → новая страница → согласие → два тестовых FAQ.
