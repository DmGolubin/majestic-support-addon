# Предпочтения библиотеки аккаунта — 18 октября 2026

Задача C11 выделена из C08. Реализовано в исходниках; живая приёмка после включения API остаётся в C09. Новых запросов к панели в этой работе не выполнялось. Владелец подтвердил, что API ещё выключен. Установленный Discord не менялся.

## Поведение

- Избранное, бинды, недавние, частота использования, префикс, состояние превью и выбор проекта Tech сохраняются отдельно для каждого Discord ID.
- Записи находятся в локальном DataStore адаптера, ключ `SupportTemplates_panel_preferences_v1_<DiscordID>`. Это предпочтения устройства, а не синхронизация с сайтом. Данные локальной библиотеки и демо не мигрируют автоматически.
- Формат ограничен перечисленными полями, корректными ID и сочетаниями клавиш. Тексты/названия FAQ, личные шаблоны, папки и токены в эту запись не входят. Учётные данные по-прежнему обслуживает отдельное защищённое хранилище.
- После входа или восстановления сначала проверяются профиль и полный каталог сервера, затем предпочтения применяются к существующим ID. Офлайн-каталог на диск этим изменением не добавлен.
- Переименование/обновление текста сохраняет предпочтения по стабильному ID. Полный снимок удаляет ссылки на отсутствующие записи, в том числе недоступные по новым правам. Временное скрытие библиотеки при обновлении прав не считается удалением.
- Выход/отзыв немедленно убирает каталог и блокирует новые записи от старого экземпляра хранилища. Уже поставленные в очередь снимки предпочтений завершаются; следующий вход ждёт их перед чтением. Несекретные предпочтения остаются на устройстве для будущего разрешённого входа того же аккаунта.
- При ошибке чтения прежняя запись не перезаписывается значениями по умолчанию. Текущий сеанс работает с временными настройками, об этом сообщает раздел подключения.
- При ошибке записи изменения остаются в памяти; кнопка «Повторить сохранение» повторяет запись без выхода и потери этих изменений. При закрытии процесса до успешного сохранения несохранённые изменения могут потеряться.

## Проверки и исправления ревью

38 тестов адаптера: разделение аккаунтов, допустимые ID, безопасная проекция, повреждённые поля, границы объёма, прототипы, порядок записей и ошибки хранилища.

10 новых тестов настоящего контроллера с подменёнными HTTP/Discord/DataStore: перезапуск с новым текстом FAQ, два аккаунта с одинаковыми ID шаблонов, изменение прав, удаление записи, отказ восстановления, ошибки чтения/записи, выход во время чтения и очередь записи при повторном входе.

Независимое ревью выявило два исправленных сценария:

1. После выхода настройки могли обращаться к старому routed Store и стирать сохранённые ссылки прежнего аккаунта. Теперь экземпляр закрывается для новых записей до очистки каталога.
2. Совет повторно войти при ошибке записи терял несохранённые изменения. Ошибки чтения и записи теперь различаются; для записи есть повтор без выхода. Регрессионный тест проверяет сохранённое избранное после такого повтора и нового входа.

Повторное независимое ревью не нашло оставшихся конкретных ошибок в этом объёме. Ревьюер прогнал 73 целевых теста и отдельно воспроизвёл сохранение очереди при закрытии Store и отмену устаревшего чтения предпочтений новым SSE-событием.

Проверки на финальном коде:

- `pnpm test`: 709 тестов, 36 файлов, без ошибок.
- `pnpm typecheck` и `pnpm typecheck:vencord`: успешно.
- `node scripts/check-vencord-build.mjs`: успешная изолированная сборка.
- ESLint четырёх изменённых исходных модулей в изолированной копии Vencord: без ошибок.

Локальные тесты не подтверждают работу настоящего API, долговечность DataStore конкретной установки Discord или внешний вид нового сообщения в живом клиенте. Нет гарантии сохранения последних изменений при аварийном завершении процесса; координация предпочтений между одновременно работающими процессами этим блоком не реализована.

## Живая приёмка C09

1. Войти, отметить FAQ и личный шаблон, назначить бинд, использовать шаблоны и перезапустить Discord. Проверить восстановление только после успешной проверки API.
2. Обновить текст FAQ и удалить другой шаблон на сайте: первый сохраняет предпочтения, ссылки на второй пропадают.
3. Сменить Discord-аккаунт: предпочтения и каталог прежнего не появляются. Вернуться после разрешённого входа и проверить свою запись.
4. На тестовом профиле воспроизвести отказ DataStore: сообщение об ошибке, успешное повторное сохранение, отсутствие перезаписи старых данных при отказе чтения.

Установка `.bat`, обновления через GitHub Releases, запись личных шаблонов через API и политика долговременного офлайн-каталога остаются отдельными задачами roadmap.
