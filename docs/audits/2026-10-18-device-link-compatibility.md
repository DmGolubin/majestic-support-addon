# Ссылка входа и отказ подтверждения на сайте

## Наблюдения владельца 18 октября

- Ответ выдачи кода содержит HTTPS-адрес `https://majestic-rp.tech/connect`; полная ссылка использует параметр `code`. Значения device_code и user_code в отчёт не копируются.
- Плагин показывает ошибку проверки контракта. Причина подтверждена кодом и регрессией: локальная проверка ожидала только `https://panel.majestic-rp.tech/connect` и параметр `user_code`.
- На скриншоте сайта запрос подтверждения отклонён с `csrf_failed`. Это отдельный отказ сессионного маршрута сайта. Его точная причина, HTTP-статус и серверная конфигурация по скриншоту не установлены.

## Исправление клиента

Разрешены ровно два известных HTTPS-origin для страницы `/connect`: `panel.majestic-rp.tech` и `majestic-rp.tech`. При явно заданном тестовом API-origin разрешена только его собственная страница. Полная ссылка должна содержать единственный `code` либо `user_code`, совпадающий с ответом API. Дубли, смешанные параметры, посторонние query-поля, fragment, credentials, другой порт, путь или домен отклоняются.

API и обмен токенами остаются на `https://panel.majestic-rp.tech/api/plugin/v1`. Cookies сайта, CSRF-токен и серверные секреты плагину не нужны. Браузерные сессионные маршруты плагин не вызывает, CSRF-защиту не обходит.

Регрессии используют вымышленные коды. Старый валидатор отклонял новые корректные примеры; после исправления они принимаются. Проверка PanelClient проходит через выдачу ссылки, интервал ожидания и обмен на вымышленные токены через тестовый транспорт. Это не подтверждение настоящего входа.

## Дмитрию — можно отправить

Выдача кода уже работает. Ответ возвращает `https://majestic-rp.tech/connect?code=…`. В плагине поправлена слишком узкая проверка ссылки; API и токены остаются на `panel.majestic-rp.tech`.

Отдельно на странице подтверждения нажатие «Разрешить» возвращает `csrf_failed`, активное подключение не появляется. Посмотри, пожалуйста, сессионный маршрут подтверждения: как страница получает и передаёт CSRF-токен, приходит ли ожидаемая сессионная cookie и согласованы ли origin страницы, API и настройки `SITE_URL`/`CLIENT_URL`. Это направления проверки, а не установленная причина. Подтверди также, какой из двух доменов должен быть каноническим адресом `/connect`.

CSRF отключать не нужно. После исправления повторим новый вход из плагина и проверим получение токенов, `/me`, `/snapshot` и SSE. Старую попытку и её секреты для воспроизведения не используем.
