# Установка SupportTemplates: три адаптера, одно приложение

Дата исследования: 16.10.2026. Это архитектурная рекомендация, не готовый установщик. Discord на компьютере не изменялся в рамках исследования.

## Актуальное решение от 18.10.2026

Владелец выбрал открытый урезанный форк Vencord с одним SupportTemplates. Установка — ZIP и .bat, вызывающий локальный PowerShell; обычный Vencord ставить отдельно не нужно. Происхождение и лицензии основы остаются открыты. Адаптеры обычного Vencord и BetterDiscord сохраняются. Предыдущая рекомендация загрузчика с нуля ниже — историческое сравнение, не текущий план.

Первый релиз описан в RELEASE-V1.md. Код обновляется из опубликованного проверенного GitHub Release с подтверждением сотрудника, перезапуском и откатом. Push в ветку не обновляет клиентов. Полное выделение общего UI для BD не блокирует первый форк.

Для реализации 18.10 владелец разрешил отдельный **Canary** как тестовую среду и запретил менять рабочий Stable. Прототип находится в `standalone/`: один SupportTemplates, три внутренних модуля инфраструктуры, отдельные данные, BAT/PowerShell и ZIP с исходниками. Это ещё не публичный релиз и не приёмка Stable. Текущая проверка и ограничения фиксируются в roadmap I03/I04/R09. Всё сравнение ниже описывает исследование 16.10; его первоначальный выбор Stable и исключение Canary заменены этим решением.

## Предыдущее сравнение вариантов (16.10.2026)

Требование владельца: самостоятельная установка только SupportTemplates без Vencord, BetterDiscord и собственного EXE; версии для Vencord и BetterDiscord сохраняются.

Рекомендуемый первый вариант для проверки — Windows Discord Stable, ZIP с собранными JS/CSS, небольшим загрузчиком, install.ps1, repair.ps1 и uninstall.ps1. Скрипты используют установленный Windows PowerShell; плагин исполняется внутри существующего Discord/Electron. Отдельный Node.js у саппорта не должен требоваться. Это означает отсутствие нашего EXE, а не отсутствие выполнения программ или изменений клиента.

Выбор следует подтвердить прототипом на актуальной сборке. Нет оснований обещать универсальную совместимость с будущими обновлениями Discord.

## Сравнение

| Вариант | Где работает | Оценка |
| --- | --- | --- |
| Собственный небольшой загрузчик + PowerShell + ZIP | Desktop Discord | Лучшее соответствие запросу. Требует сопровождения загрузки и внутреннего API Discord. |
| Браузерное расширение | Discord в браузере | Не требует изменения desktop-клиента, но не добавляет интерфейс в установленный Discord. Отдельный продукт, не замена для текущего сценария. |
| Ручная вставка JS через DevTools | Временная сессия | Пригодна для разработки, не для установки сотрудникам и восстановления после запуска. |
| Отдельное приложение или Electron-оболочка | Собственное окно | Дополнительное приложение и распространение runtime; не соответствует текущему требованию. |
| Урезанный форк Vencord | Desktop Discord | Может переиспользовать инфраструктуру, но фактически остаётся форком Vencord. Не выдавать его за независимый загрузчик. |
| Vencord / BetterDiscord адаптеры | Клиент с выбранным модом | Сохраняются как альтернативы для сотрудников, которые ими пользуются. |

## Что установлено по исходникам

В репозитории есть src/core и src/vencord. Собственного desktop-загрузчика и нового BD-адаптера нет. UI напрямую импортирует @webpack/common; platform.ts использует DataStore, insertTextIntoChatInputBox, Discord stores и dispatcher. index.tsx использует ChatButtons, Settings и definePlugin. Есть зависимости ErrorBoundary и clipboard. Следовательно, сборка существующего кода одним JS-файлом не устраняет зависимость от Vencord.

Исследованы локальный Vencord src/main/patcher.ts и опубликованные исходники установщиков. Vencord загружает исходный Discord через bootstrap и подключает preload; это существенно больше, чем копирование файла плагина. Метод конкретного проекта не является гарантией работы собственного загрузчика.

Первичные источники:

- [Vencord Installer: patcher.go](https://github.com/Vencord/Installer/blob/main/patcher.go) — изменение точки запуска и восстановление оригинального архива.
- [BetterDiscord Installer](https://github.com/BetterDiscord/Installer) — установка и удаление собственного загрузчика.
- [Electron: Application Distribution](https://www.electronjs.org/docs/latest/tutorial/application-distribution) — структура приложения и ASAR.
- [Electron: ASAR Integrity](https://www.electronjs.org/docs/latest/tutorial/asar-integrity) — проверка целостности поддерживается на Windows и зависит от конфигурации приложения. Возможность изменения конкретной сборки Discord нужно проверить; наличие Electron само по себе её не доказывает.

## Архитектура

Общие core + UI + API-клиент, затем три адаптера: standalone, Vencord и BetterDiscord. Отдельно сборка и установка каждого варианта. Одна кодовая база не означает один бинарный файл для трёх сред.

Сначала вынести зависимости из UI в собственные интерфейсы: React/рендер, открытие меню, канал и редактор, вставка текста, события тикетов, хранилище, уведомления, буфер, открытие браузера, защищённое хранение токенов. Для каждого адаптера проверить возможности: отсутствие одной функции не должно ломать весь Discord. В standalone придётся поддерживать собственный доступ к нестабильным модулям Discord; Vencord больше не будет делать это за нас.

Standalone runtime загружает только SupportTemplates. Каталог сторонних плагинов, общий менеджер модов и произвольное исполнение кода с панели не нужны. API панели отдаёт данные; JS обновляется отдельным проверяемым пакетом релиза. При переиспользовании чужих файлов сохранять их авторство и лицензии; публичный репозиторий сам по себе не заменяет проверку лицензий зависимостей.

## Установка для сотрудника — целевой сценарий

1. Скачать опубликованный ZIP релиза и распаковать в устойчивое расположение либо позволить скрипту скопировать runtime в пользовательскую папку SupportTemplates.
2. Запустить локальный установочный скрипт. Он показывает найденный Discord, версию и выбранный путь; не требует сборки исходников или Node.js.
3. Закрыть Discord перед изменением файлов. Установщик проверяет совместимость, чужие загрузчики, делает проверяемую резервную копию и устанавливает bootstrap.
4. Открыть обычный Discord привычным способом. В меню SupportTemplates войти через панель.

Конкретный путь bootstrap выбирается после прототипа по фактической структуре Discord. Не применять вслепую старые инструкции для discord_desktop_core. Не устанавливать второй загрузчик поверх Vencord/BD: предложить соответствующий адаптер. Чужие патчи не удалять автоматически.

PowerShell может быть ограничен политикой организации или блокировкой скачанных файлов. Установка должна показывать понятную причину и документированный способ запуска, не менять глобальные политики безопасности. Обещать двойной клик без ограничений нельзя. Для системной установки Discord права могут отличаться; первый целевой вариант — установка в профиле пользователя.

## Обновления, восстановление, удаление

- Обновление FAQ через API не равно обновлению исполняемого плагина.
- Для первого прототипа достаточно ручного обновления ZIP и команды repair после обновления Discord. Автоматическую самопочинку не объявлять готовой.
- Для релиза нужны версия пакета, совместимость, проверка происхождения и целостности, атомарная замена, предыдущая рабочая версия и откат. Один хеш, скачанный рядом с архивом, не доказывает авторство; схему подписания релизов нужно спроектировать отдельно.
- При ошибке загрузки должен быть проверенный путь запуска обычного Discord без плагина; неизвестная сборка не должна патчиться вслепую.
- Удаление восстанавливает оригинальные файлы только той версии, для которой сделана копия. Нельзя переносить старый app.asar в новую версию. Удалять только собственные проверенные файлы.
- Удаление локального токена и отзыв серверной сессии — разные действия. При доступной сети отозвать подключение; офлайн сообщить о необходимости отключить устройство на панели.
- Безопасное хранение refresh-токена нужно реализовать и проверить для каждой среды; обычные настройки плагина не считаются защищённым хранилищем.

## Порядок работ и критерий продолжения

1. Общий слой адаптеров без регрессий текущего Vencord.
2. Изолированный standalone-прототип: установка, запуск только нашего runtime, отключение, удаление и восстановление Discord. Проверка на текущей Windows Stable; не трогать рабочую установку без отдельного шага внедрения.
3. Подключить интерфейс и функции к standalone. Проверить основной чат, ветку сбоку, редактирование сообщения, хоткеи, lifecycle и токены.
4. Упаковать ZIP, repair/uninstall, обновление и откат. Проверить прерванную установку, повторную установку, обновление Discord, чужой загрузчик, пути с пробелами, повреждённый пакет и запуск без сети.
5. Сделать новый BetterDiscord-адаптер на общем ядре; выпускать параллельно с Vencord и standalone.

Если прототип не обеспечивает надёжный запуск и восстановление на целевой сборке, standalone остаётся незавершённым. Временная проверка на Vencord не является приёмкой самостоятельной версии. macOS, Linux, PTB, Canary и Store-установка не входят в обещанную поддержку этого первого прототипа.

## Что нужно Дмитрию

API входа, шаблонов и уведомлений остаётся общим для трёх адаптеров. Можно передавать platform и app_version для диагностики, но они не доказывают доверенность клиента. Загрузчик и установочные скрипты относятся к плагину, а не к Telegram-боту. Раздача пакетов через панель и автоматическое обновление кода — отдельная последующая договорённость; они не блокируют создание API.
