# SupportTemplates — Canary prototype

Открытая отдельная сборка на основе Vencord. Один пользовательский плагин SupportTemplates; внутренние модули обеспечивают кнопку, настройки и извлечение компонентов Discord. Обычный Vencord-плагин сохраняется в основном репозитории.

## Установка

1. Распакуйте ZIP целиком в обычную папку. Не запускайте BAT внутри архива.
2. Полностью закройте **Discord Canary**, включая трей. Рабочий Discord Stable закрывать не нужно.
3. Запустите `status.bat`, затем `install.bat`. Канал по умолчанию — Canary.
4. Запустите Canary обычным способом. Настройки доступны в разделе SupportTemplates и из окна шаблонов.

`repair.bat` восстанавливает подключение после обновления Discord. `uninstall.bat` возвращает исходный Discord, сохраняя настройки. `rollback.bat` переключает на предыдущую установленную версию, если она есть. Установщик не закрывает процессы и отказывается перезаписывать чужой Vencord/BetterDiscord. Точные параметры и результат сообщает PowerShell-скрипт.

Это тестовый пакет. Настоящий вход/FAQ/SSE требуют выданного панелью доступа. Обновлятор upstream Vencord исключён; обновления SupportTemplates использует собственный общий движок.

## Автоматические обновления

Версия, канал выпусков и GitHub-репозиторий берутся из `distribution/config.json` и входят в проверяемый payload как `runtime/update-config.json`. Проверка выполняется при запуске и затем примерно раз в 6 часов. `releaseRepository: null` отключает сеть. Сейчас указан `skyjacc/support-templates`; до открытия репозитория анонимный ответ 404 означает недоступный канал обновлений. Запроса входа и встроенных токенов нет. Подготовка к публикации не означает, что релизы уже опубликованы или прошли живую приёмку.

Общий движок проверяет канал, версию, GitHub-метаданные, размер и SHA-256 ZIP, затем сохраняет пакет в `auto-updates/` каталога установленного канала. После загрузки появляется уведомление. Скрытый PowerShell-помощник ждёт полного выхода из выбранного Discord, включая трей, повторно проверяет ZIP и запускает проверенный `SupportTemplates.ps1 -Action Install`. Другой канал Discord закрывать не нужно. Процессы не завершаются принудительно; планировщик задач и автозапуск не используются. Запустите Discord снова после завершения установки. Если запустить его слишком рано, установщик откажется менять работающий runtime; пакет останется для повторной попытки после следующего выхода.

Автоматический путь всегда устанавливает **полный пакет после выхода**, в том числе для выпуска с совместимым интерфейсом. Во время работы код и черновики не меняются, принудительной перезагрузки нет. Сохраните несохранённые черновики перед обычным выходом. Ошибка сети не мешает запуску Discord. Сохранённый пакет повторно проверяется при следующем запуске; ошибки установщика записываются в `auto-updates/apply-*/installer.log`. Устаревшие пакеты не устанавливаются: движок сравнивает версию при запуске, а помощник повторно проверяет установленную версию под блокировкой установщика. Запись об успешном обновлении создаётся только после проверки установленного состояния.

## Обновление через Ctrl+R

Для уже установленного плагина запустите `update.bat` из нового распакованного пакета, затем нажмите **Ctrl+R в Canary**. Выходить через трей не требуется. Перед перезагрузкой сохраните открытый черновик редактора шаблонов.

Режим проверяет совместимость исполняемого кода загрузчика, main и preload. Если они изменились, обновление откажется менять файлы и укажет необходимость полной установки. Для совместимых выпусков JavaScript и стили интерфейса заменяются единым атомарным файлом. Native runtime, настройки и сессия остаются прежними; `status.bat` показывает отдельно базовую версию и версию интерфейса. Полная установка позже переводит весь runtime на выбранную версию.

Если операция прервалась, повторите `update.bat`: журнал и проверенные копии позволяют завершить замену. Проверка статуса ничего не меняет. Этот ручной режим не используется автоматическим помощником.

## Данные и проверка

Данные и версии находятся отдельно в `%LOCALAPPDATA%/SupportTemplates/channels/<канал>/`. IndexedDB использует отдельное имя. Чужие настройки Vencord не импортируются. Сохранённые токены используют прежнее защищённое хранилище плагина.

`manifest.json` фиксирует версии и SHA-256 файлов payload. Это проверка целостности локального пакета, **не цифровая подпись издателя**. Автоматическое обновление доверяет HTTPS и правам публикации в настроенном GitHub-репозитории; общий release manifest дополнительно фиксирует хеш всего ZIP, включая установщик. При извлечении запрещены выход за каталог, ссылки, дубли путей и специальные имена Windows.

## Исходники

`source.tar` содержит точный подготовленный исходник основы и плагина, общий движок и конфигурацию `distribution/`, lockfile и `compile.mjs`. Все входы `src/`, `standalone/` и `distribution/` замораживаются через `git archive`; грязные входы останавливают сборку. Версия интерфейса и идентификатор исходного коммита записываются только в подготовленную копию `buildInfo.ts`. Исходный коммит Vencord указан в manifest. Лицензия GPL-3.0-or-later и исходное авторство сохранены; дополнительные notices находятся в исходниках и `*.LEGAL.txt` сборки. Формат маленького загрузчика соответствует [Electron ASAR](https://github.com/electron/asar/blob/main/src/disk.ts).

Для повторной сборки runtime: распаковать `source.tar` в отдельную папку, установить зависимости указанной в package.json версией pnpm с `--frozen-lockfile`, выполнить `node compile.mjs`. Версии инструментов этой сборки записаны в `build-evidence/toolchain.json`. Полный рецепт из `standalone/` репозитория SupportTemplates также приложен в `build-recipe/`. Публичная публикация этого прототипа не выполнялась.

Если конфигурация отсутствует, указывает на другой канал или перенаправленный путь, либо runtime отсутствует, загрузчик до запуска плагина открывает исходный Discord. Ошибка внутри уже запущенного runtime не запускает Discord второй раз: для такого случая предусмотрены запуск Canary с `--vanilla` и восстановление через BAT.
